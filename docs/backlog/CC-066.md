# CC-066 — isVercelRuntime() false-positives on a linked project's local VERCEL_OIDC_TOKEN

## Problem

`src/lib/contracts/kms-signer.ts:61-63`:

```ts
function isVercelRuntime(): boolean {
  return Boolean(process.env.VERCEL) || Boolean(process.env.VERCEL_OIDC_TOKEN);
}
```

Found while running the CC-059 step 3 verification. Running `vercel link` against this project
(needed to authenticate the CLI after four months dormant, see CC-059's 2026-08-08 update) makes
the Vercel CLI append a `VERCEL_OIDC_TOKEN` to the local `.env.local` — this is normal, documented
Vercel CLI behaviour for pulling dev-environment variables, not a bug in the CLI. But it means any
local script or `npm run dev` session that loads `.env.local` after running `vercel link` now has
`VERCEL_OIDC_TOKEN` set, which flips `isVercelRuntime()` to `true` and routes KMS signing down the
Workload Identity Federation branch (`kms-signer.ts:80-115`) instead of the local
Application-Default-Credentials branch — even though the code is not running on Vercel at all.
That branch immediately throws because `GCP_PROJECT_NUMBER` / `GCP_WORKLOAD_IDENTITY_POOL_ID` /
`GCP_WORKLOAD_IDENTITY_POOL_PROVIDER_ID` / `GCP_SERVICE_ACCOUNT_EMAIL` aren't set locally (correctly
so — WIF is a Vercel-runtime-only mechanism per this same file's own comment at line 57-59).

Reproduced directly: after `vercel link`, `node --env-file=.env.local <script importing
resolveDisputeOnChain>` failed with `GCP Workload Identity Federation env vars not set`; deleting
`VERCEL_OIDC_TOKEN` from the env before running fixed it immediately.

This is a real footgun for local dev/testing on any machine where the Vercel CLI has been linked —
which, after today, includes this developer's main rig. It doesn't affect production (where
`VERCEL=1` is also set and correct), but it silently breaks local KMS testing in a way whose error
message doesn't hint at the actual cause (a stray env var from an unrelated CLI command).

## Fix

Check `process.env.VERCEL` alone — that's the flag Vercel's own runtime sets
(https://vercel.com/docs/projects/environment-variables/system-environment-variables), and is not
present in a local shell regardless of whether `vercel link`/`vercel env pull` has ever been run.
Confirm nothing in this codebase currently relies on the `VERCEL_OIDC_TOKEN` half of the check
before removing it — `grep -rn "VERCEL_OIDC_TOKEN" src`.

## Acceptance

- Local `.env.local` containing a `VERCEL_OIDC_TOKEN` (from `vercel link` or `vercel env pull`)
  does not change which KMS auth path `kms-signer.ts` takes.
- `npm run verify:kms` (or equivalent) still works both with and without that var present locally.
