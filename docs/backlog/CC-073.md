# CC-073 — Dashboard has no way to add or manage notification channels

## Problem

Found while sweeping the `/learn` docs against what the dashboard actually offers. The
`notification_channels` table and the `register_notification_channel` MCP tool
(`src/lib/mcp/server.ts`) support four channel types — `email`, `webhook`, `telegram`, `discord`
(`supabase/migrations/002_notification_channels.sql:9`) — but **none of this is reachable from
`/dashboard` or `/connect` today**:

- `/connect` has one optional field, "Contact Email," which sets a single `type: "email"` channel
  at registration time (`src/app/api/register/route.ts`) and nothing else.
- There is no way to add, change, or remove a notification channel afterward.
- Webhook, Telegram, and Discord channels are entirely unreachable except by calling
  `register_notification_channel` directly over MCP — which means, in practice, nobody using the
  website has ever set one.

Aaron confirmed: no phone/SMS channel is wanted — the four existing types are the right set. This
issue is purely about giving the dashboard a way to manage them, not about adding a fifth type.

## Fix

Add a section to `/dashboard` (or a dedicated settings view) that:
- Shows the contractor's current notification channel(s), if any.
- Lets them add/update a channel of any of the four supported types, with clear guidance on what
  "address" means for each (an email address; a URL for webhook; a chat ID for Telegram/Discord —
  the last two probably need a short explainer, since "chat ID" isn't obvious to a non-technical
  user).
- Lets them remove a channel.

This is the API surface already tested and working via MCP (`CC-069`'s live registration used the
same underlying `registerNotificationChannel` DB function) — this issue is a UI layer on top of
existing, working backend capability, not new backend work.

## Acceptance

A worker can add, change, and remove a notification channel entirely from the website, without
needing to call the MCP tool directly.

Related: `CC-074` (the auto-booking toggle depends on being able to set a channel type other than
email in the first place, since accepting bookings without human review is the whole point of the
webhook/agent path), `docs/learn/module-5` (describes this capability; should link here once built
rather than describing it as MCP-only).
