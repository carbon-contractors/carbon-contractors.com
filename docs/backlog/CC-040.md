# CC-040 — Production monitoring and alerting

Migrated from NOR-305. Nothing currently watches production — the site was up for four
months unattended and the only reason that was survivable is that no real money was moving.

## Scope
- Error alerting: Vercel log drain, or Sentry
- On-chain: `CarbonEscrow` event monitoring, KMS signing failures, deployer ETH balance
  (the balance alert becomes moot if CC-033 lands)
- Uptime: external monitor against `/api/health`, which already reports database, escrow
  contract and session health
- A runbook per alert type, so a 2am page has a documented response

Related: CC-033, CC-039.

## Update 2026-08-13 — split by `ADR-0003`; this ticket keeps the operational half

`ADR-0003` rescopes and splits this issue. The correctness half is now **`CC-085`**.

**What moved out.** Everything protecting correctness, fund safety or a published claim — the
invariant monitors — and it moved *ahead* of `CC-077`/`078`/`079` rather than staying day-of. The
reasoning: the ADRs introduced failure modes that are **silent**, where the system keeps working and
produces wrong outcomes without erroring. The lifecycle tests are the next real work item, and the
invariant monitors are how you know the lifecycle actually worked.

**What stays here.** Availability monitoring, and this issue's "day-before-launch, or you're just
watching an empty coming-soon page" reasoning remains correct for it: Sentry for application errors,
an external uptime monitor against `/api/health`, on-chain event monitoring, and re-pointing at
mainnet addresses under `CC-039`.

**Scope reductions from `ADR-0001` Amendment 1**, recorded so they are not reinstated from the older
text above:

- **No platform transaction monitoring in the settlement path** — post-Amendment 1 the platform does
  not transact at all. Verdicts are EIP-712 signatures handed to the parties, and the worker claims.
- **Deployer ETH balance alerting is moot for settlement.** It remains relevant only for deployment
  and ownership operations. (Already flagged here as dependent on `CC-033`.)
- **"KMS signing failures" shrinks** from an on-chain failure monitor to `verify-signer` — a health
  check that the signer can produce a signature at all. That lives in `CC-085`.

The `CC-051` threshold instrumentation noted above also moves to `CC-085`, as an eighth monitor.

Priority stays **P1**, still day-of.

Related: `ADR-0003`, `CC-085`, `CC-086`, `CC-039`, `CC-033`, `CC-051`.

## Update 2026-09-16 — CLOSED: the operational half, shipped

`ADR-0003` handover step 6 was this ticket's remaining scope: error alerting wired up,
external uptime monitoring, on-chain event monitoring, and the per-alert runbook. All
four shipped on branch `feat/cc-040-ops-monitoring`, verified live against production
and Base Sepolia before opening the PR. The day-of sequencing is satisfied by
construction: the monitors run hourly against the live site and chain starting the
moment this merges.

### The defect found on arrival

Picking this ticket up found the scheduled monitors watching the **wrong escrow**.
`monitors.yml` still pinned `0xe80d…` — the 2026-08-15 deployment superseded by the
CC-082 v2 redeploy of 2026-09-01 (`0xc6aa…E4d3`, block `46227900`, per
`Security-Trust-Disclosure.md`) — so for 15 days every hourly run verified an empty
contract: `verify-escrow-solvency CLEAN` against `totalLocked 0`. The exact silent
wrong-escrow class the `/api/health` identity fields were added to catch, living in
the workflow the health route feeds. Re-pointed as part of this closure, with the
incident recorded in a comment block where the next redeployer will read it.

### What shipped

| File | What it does |
| :-- | :-- |
| `src/instrumentation.ts` | Next `onRequestError` hook: every uncaught request error gets a structured `request_error_uncaught` log line (masking-aware logger) and a deduped relay to `MONITOR_WEBHOOK_URL` — class + route + digest only, never the message (CC-009/ADR-0002 D9). This is "error alerting wired up": the relay IS the log drain, running where the logs are produced. Sentry deliberately not used — dependency freeze; the webhook covers every property this needed. |
| `scripts/audit/verify-uptime.mjs` | The GitHub-hosted half of the external uptime monitor: fetches production `/api/health`, asserts every subsystem check, and **pins the escrow identity** — a healthy site answering from the wrong contract is a MISCONFIG, not a pass. TRANSIENT/FAIL/MISCONFIG exit-code classes match the invariant-monitor conventions. |
| `scripts/audit/verify-privileged-events.mjs` | On-chain event monitoring per ADR-0003 D5 (scheduled getLogs, no indexer): replays the escrow's full `OwnershipTransferred`/`VerdictSignerUpdated` history in chunked ranges and matches every event against the committed allowlist. An unauthorised owner or signer change — the compromise case — is the one thing this monitor exists to catch. |
| `scripts/audit/privileged-allowlist.mjs` | The committed allowlist + pure matcher, extracted so it is unit-testable. The first inline draft shipped a field-name bug (`from`/`to` vs decoded `previousOwner`/`newOwner`) that live-running caught; the extraction and its tests are the defence against that class recurring. |
| `scripts/audit/run-monitors.mjs` | Registry gains `verify-uptime` (tier `wake`) and `verify-privileged-events` (tier `wake`); the schedule now runs 10 monitors. |
| `.github/workflows/monitors.yml` | Escrow re-pointed to `0xc6aa…E4d3`, deploy block to `46227900`; `UPTIME_TARGET_URL` and `EXPECTED_ESCROW` wired inline as public facts, per the file's own convention. |
| `docs/runbooks/INVARIANT-ALERTS.md` | §3 gains Invariant 5 (uptime, with the wrong-escrow MISCONFIG variant spelled out), Invariant 6 (privileged events — authorised rotation vs compromise), and the application-error relay section. Every alert type now has a runbook. |
| `docs/backlog/CC-111.md` | The PO-action residue: the independent external uptime account (ADR-0003 D5's second path — a monitor on GitHub cannot report GitHub failing) and the `MONITOR_WEBHOOK_URL` Vercel env var the error relay needs. |
