# CC-040 — Production monitoring and alerting

Migrated from NOR-305. Nothing currently watches production — the site was up for four
months unattended and the only reason that was survivable is that no real money was moving.

## Scope
- Error alerting: Vercel log drain, or Sentry
- On-chain: `CarbonEscrow` event monitoring, KMS signing failures, deployer ETH balance
  (the balance alert becomes moot if CC-033 lands)
- Uptime: external monitor against `/api/health`, which already reports database, escrow
  contract and session health
- A runbook per alert type, so a 2am page has a documented response

Related: CC-033, CC-039.

---

## Update 2026-08-10 — reclassified: public-launch, not mainnet

"The site was up for four months unattended" already happened on testnet — real users hitting an
unmonitored site is a launch-day risk, not something that waits for mainnet. `CC-058` (Supabase
tier) is already done, which removes one failure mode this would have needed to catch; the rest
of the scope here (error alerting, on-chain event monitoring, uptime) stands.

## Update 2026-08-10 (2) — partially covered by paid tiers; the rest is a day-before-launch task

Aaron: Vercel Pro and Supabase Pro (both purchased this session — see `CC-058`, `CC-063`) already
cover part of this scope — Vercel Pro includes better logging/observability than Hobby, Supabase
Pro includes daily backups and a proper dashboard, and the "unattended for four months" failure
mode specifically (`CC-058`) is closed.

**Not covered by the paid tiers, still needed:** error alerting actually wired up (a Vercel log
drain or Sentry, not just logs existing to be read manually), on-chain event monitoring
(`CarbonEscrow`, KMS signing failures), and the runbook.

Sequencing: this is a **day-before-launch** task, same as `CC-035` — set up monitoring right
before the gate lifts, not weeks earlier where it would just be watching an empty coming-soon
page.
