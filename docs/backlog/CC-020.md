# CC-020 — Rate limiter claims Upstash Redis but is per-instance in-memory

The header comment at `middleware.ts:5-8` describes distributed rate limiting via Upstash
Redis. The implementation at `middleware.ts:30-108` is an in-memory `Map`. There is no
Upstash code in the repo, despite `UPSTASH_REDIS_REST_URL`/`_TOKEN` sitting in `.env.local`
and a commit titled "added upstash_redis".

Across Vercel serverless instances a per-instance map is close to useless — the effective
limit is 60/min multiplied by however many instances are warm.

Fix: either implement the Upstash-backed limiter the comment describes, or correct the
comment and accept the weaker guarantee explicitly. Do not leave the docs lying.
