# CC-010 — Brand-new worker sees a reputation score of 0 and is told to go register

## Problem
Two bad first impressions immediately after signup:

1. `src/lib/reputation/compute.ts:44-64` returns 0 across every component for a worker with
   zero tasks and zero stake, so the dashboard renders a large "**0** Reputation"
   (`src/app/dashboard/page.tsx:299-341`). Meanwhile `src/app/api/register/route.ts:139`
   wrote `reputation_score: 50` to the DB, so the number shown contradicts the number stored
   — and MCP search ranks on the stored column (`src/lib/db/whitepages.ts:31`).

2. The zero-task empty state (`src/app/dashboard/page.tsx:445-454`) says "Make sure you've
   registered your services" and links back to `/connect` — which the user completed two
   seconds earlier (`src/app/connect/page.tsx:25`).

## Fix
- Render a "New — no history yet" state instead of a bare 0.
- Reconcile the seeded 50 against the computed score; pick one source of truth and document it.
- Branch the empty state on whether a profile exists: if it does, say "You're listed —
  agents can now find you. No tasks yet."

## Acceptance
A freshly registered worker sees a dashboard that reads as success, not failure.
