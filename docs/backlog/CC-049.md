# CC-049 — Merge the stranded key-compromise recovery runbook

## Problem
NOR-195 / AUD-010 was **done but never merged.** Commit `8df1c7f`
("docs(security): add key compromise recovery runbook") sits on the unmerged remote branch
`origin/claude/nor-195-recovery-runbook`, dated 2026-04-26. It adds
`docs/Key-Compromise-Recovery.md` and touches `SECURITY.md` and the keep-alive workflow.

Because the branch predates the fast-forward, a naive merge would look like it deletes the
whole backlog. Cherry-pick the relevant file instead of merging the branch.

## The underlying problem it documents
The contract uses OpenZeppelin `Ownable`. `transferOwnership()` rotates `resolveDispute()`
authority, but `completeTask()` checks `msg.sender == task.agent` against the original key —
so tasks already in flight get stuck if the key rotates. The documented recovery path is
dispute → `resolveDispute(taskId, true)` under the new owner, done manually.

## Do
1. `git cherry-pick 8df1c7f` (or copy `docs/Key-Compromise-Recovery.md` across), resolve the
   keep-alive conflict against CC-006, then delete the branch.
2. Consider a `completeTaskByOwner(taskId)` emergency function in the next contract version —
   it is the clean fix, and there is a natural window to add it at the mainnet deploy (CC-034).

Related: CC-006, CC-034, CC-039.
