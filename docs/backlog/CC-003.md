# CC-003 — CSP blocks Coinbase wallet RPC and passkey endpoints in production

## Problem
`next.config.ts:37` restricts `connect-src` to `'self' *.supabase.co sepolia.base.org mainnet.base.org`.

OnchainKit's default wagmi transport talks to
`https://api.developer.coinbase.com/rpc/v1/base-sepolia/<apiKey>`, and the `Name`/`Avatar`
identity components resolve through the same host. The passkey flow runs in an iframe from
`https://keys.coinbase.com`, and `frame-src` is not declared so it falls back to
`default-src 'self'`.

All of that is blocked in production. Wallet connect will fail on the live site even though
it works locally, because local dev has a different CSP path.

## Fix
Add to `connect-src`: `https://api.developer.coinbase.com https://keys.coinbase.com https://*.coinbase.com`.
Add an explicit `frame-src https://keys.coinbase.com`.
Then verify with the browser console open on the deployed site, not just locally.

## Acceptance
Zero CSP violations in the console during a full connect → sign → register cycle on production.

## Update 2026-07-25 — confirmed, and worse than described

Read the actual header. `next.config.ts` emits:

```
default-src 'self'
connect-src 'self' https://*.supabase.co https://sepolia.base.org https://mainnet.base.org wss://*.supabase.co
frame-ancestors 'none'
```

There is **no `frame-src` directive at all**, so the `keys.coinbase.com` passkey iframe falls back
to `default-src 'self'` and is blocked outright. And `connect-src` has no
`api.developer.coinbase.com`, which is where OnchainKit's default transport and the `Name`/`Avatar`
identity components send their requests.

### Why this was never noticed
All testing used the Coinbase Wallet **browser extension** (see CC-055). The extension handles
signing in its own popup and proxies RPC through its own background context, so neither the
blocked iframe nor the blocked RPC host is ever touched. The defect is invisible to the person
testing and total for everyone else.

### Also check — Permissions-Policy
`next.config.ts` sets `Permissions-Policy: camera=(), microphone=(), geolocation=()`. WebAuthn in a
**cross-origin iframe** additionally requires `publickey-credentials-get` to be delegated to that
origin. OnchainKit should set the `allow` attribute on the iframe itself, but page-level policy can
still interfere. If the passkey dialog opens and then fails silently after the CSP fix, this is the
next thing to look at.

### Verification
Not "it works locally." Test on the deployed site, in a profile with **no Coinbase extension
installed**, console open, zero CSP violations through a full connect → sign → register cycle.
