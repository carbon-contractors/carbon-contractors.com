# CC-115 — Sitewide monospace type is small and grey-on-black prose strains reading

## Problem

The PO click-through filed two UI complaints that are one design issue:

1. **NOR-341 — "Website font is small."** The entire site renders in
   Roboto Mono with body text at 13–15px and helper text at 9–11px.
   Monospace at reading sizes is objectively ~10% wider per glyph than
   the equivalent sans, so the same px value reads smaller.
2. **NOR-350 — "White on black and green text."** The complaint resolves
   to the Base-brand black background paired with muted-grey prose
   (`--cc-text-secondary #b1b7c3`, muted `#717886`) — grey-on-black
   strain — plus green used on some content text.

Confirmed direction (PO, 2026-09-24): **Base palette/feel × GitHub-docs
typography & readability.**

## Fix

- Typography: Inter (sans) added alongside Roboto Mono. Sans is the
  default prose/UI face at 16px/1.6; mono is retained for code,
  eyebrows, and numeric labels — the Base-brand terminal feel stays in
  the chrome, not the prose.
- Readability: muted/faint greys lifted toward GitHub's dark-docs
  greys (`#82898f`/`#6e7681`); markdown prose paragraphs to
  `#c9d1d9` at 16px/1.75.
- Type scale bumps: learn subtitle 14→16, card descriptions 13→14,
  nav titles 13→14; `MarkdownContent` 15→16px.
- Green audit: remaining `--cc-green` uses are accents — eyebrows,
  hover states, code inline, blockquote rails, badges — which is
  correct brand usage, not prose. No green body text remains.

## Acceptance

- Long-form pages (Learn, legal, MCP docs) render in sans at ≥16px with
  dark-docs grey prose.
- Mono remains visible where it carries meaning (code, eyebrows).
- Green no longer paints any paragraph or long-form sentence.

## Closed

Implemented on `feat/ui-content-readability` (2026-09-24) — see PR for
the diff and test evidence.
