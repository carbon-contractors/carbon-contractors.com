# CC-114 — "Sign out everywhere" leaves the current browser looking signed in

## Problem

NOR-347: the server side of revoke-all is correct — `revokeAllSessions`
revokes every live row including the caller's own session, and the route
clears the cookie. But the dashboard's client state survived: the page kept
showing the connected view, and the next 401-triggered `fetchWithSession`
retry would silently mint a **new** session (pre-CC-112 behaviour), so on this
browser it looked like nothing happened and on other browsers nothing was
enforced until a reload.

A "sign out everywhere" that doesn't visibly sign out the device in front of
you is not a sign out.

## Fix

`handleRevokeAllSessions` now flips the dashboard into the signed-out view
(the same sign-in gate CC-112 introduced): sessions cleared, tasks cleared,
`needsSignIn` set. Re-authenticating requires the explicit gesture-owned
button — the page never re-mints on its own.

## Acceptance

- [ ] Clicking "Sign out everywhere" immediately replaces the dashboard content
  with the sign-in gate on the current browser.
- [ ] No background fetch after revoke-all mints a new session without a click.
- [ ] Other browsers' sessions are revoked server-side (existing behaviour,
  unchanged — it was never the bug).
