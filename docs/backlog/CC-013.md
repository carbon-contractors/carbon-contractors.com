# CC-013 — No robots.txt or sitemap.xml

## Problem
Neither `public/` nor `src/app` contains `robots.*` or `sitemap.*`, yet `middleware.ts:22-23`
already bypasses those paths in anticipation of them.

## Fix
Add `src/app/robots.ts` and `src/app/sitemap.ts`. While the gate is on, robots should
disallow everything except `/`; flip to allow when launching. Include `/learn/*` and
`/services` in the sitemap — the learn modules are the main SEO surface.

## Done 2026-08-25 — feat/cc-013-robots-sitemap

Shipped `src/app/robots.ts` and `src/app/sitemap.ts` (Next.js App Router
`MetadataRoute` convention). `src/lib/__tests__/robots-sitemap.test.ts` covers both.

**Gate logic** — same predicate as `middleware.ts` and `src/app/page.tsx`
(`process.env.NEXT_PUBLIC_COMING_SOON !== "false"`, fails closed, inlined at build time):

- **Gate ON** (current default): `User-Agent: *`, `Allow: /$`, `Disallow: /`, plus
  `Sitemap: https://carbon-contractors.com/sitemap.xml`. `$` pins the homepage exactly;
  `Disallow: /` covers everything else. (`Allow: /` + `Disallow: /*` would let the
  longer `/*` win for `/` as well under Google's most-specific-rule.)
- **Gate OFF** (`= "false"`): `Allow: /`, `Disallow: /api/, /dashboard, /connect` —
  public site indexable, app/API surfaces stay out.

**Sitemap** — `/`, `/learn`, `/services`, plus every `LEARN_MODULES` slug as
`/learn/<slug>` (7 modules → 10 URLs total), derived from `src/lib/learn/modules.ts`
so a new module is included automatically. Host is the `SITE_URL` constant
(`https://carbon-contractors.com`) exported from `robots.ts`, matching `layout.tsx` —
deliberately not `NEXT_PUBLIC_BASE_URL`, which is the x402 fund URL defaulting to
localhost.

Verified: new tests (6) + full vitest suite (624 tests), lint, typecheck, and
`npm run build` — `.next/server/app/robots.txt.body` and `sitemap.xml.body` generate
with the gate-on shape and all 10 URLs. Live crawl/card validation remains deferred to
`CC-039` alongside `CC-012`.
