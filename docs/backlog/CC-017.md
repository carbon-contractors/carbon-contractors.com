# CC-017 — scripts/seed.ts still writes the pre-migration-008 skills column

`scripts/seed.ts:34,41,48,55,62` inserts a `skills` column with the old tech skill values
(`solidity`, `typescript`, `zk-proofs`, …). Migration `008_rename_skills_to_categories.sql`
renamed that column, so `npm run seed` now fails with "column skills does not exist".

Fix: rewrite against `categories`, using slugs from `src/lib/categories.ts` and respecting
the max-2 rule. Worth doing early — seed data makes the whitepages demoable.

## Done 2026-08-21 — fixed on `feat/cc-010-011-017-dashboard-onboarding-and-seed`

`scripts/seed.ts` rewritten:

- `skills` → `categories`, using slugs from `src/lib/categories.ts`, max 2 per worker (the file
  now imports `validateCategorySelection` and refuses to run if a seed row violates it).
- **Wallets lowercased.** The old checksummed demo addresses would have failed migration 014's
  `CHECK (wallet = lower(wallet))` (`CC-002`) — the script was broken twice over, and fixing only
  the column name would have swapped one error for another.
- `SEED_HUMANS` is now exported and `seed()` only runs when the script is invoked directly
  (`import.meta.url` vs `process.argv[1]`), so `scripts/__tests__/seed.test.mjs` can import the
  data without triggering the env guards. The test pins all four invariants: no `skills` key,
  valid bounded category slugs, lowercase wallets, unique wallets.

Not done here: actually running `npm run seed` against the live Supabase project. The local
service-role key is the placeholder (see CLAUDE.md), so a real seed run needs Aaron's environment;
the script and its data are now verified correct without it.
