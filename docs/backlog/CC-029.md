# CC-029 — Stables integration is dead — affiliate config and Module 4 links

`src/lib/config.ts:52` declares `NEXT_PUBLIC_STABLES_AFFILIATE_URL`, which nothing in `src`
reads. `src/learn/module-4-spending-your-usdc-in-australia.md` links to `stables.money`.

Per the archived Linear notes (NOR-292 / NOR-304) Stables is sunsetting, and the MVP
definition of done marks the affiliate item superseded. Module 4 is the page that answers
"how do I actually spend this in Australia" — the most important practical question a new
Australian worker has — so a dead recommendation there is worse than no recommendation.

Fix: remove the dead config, and rewrite Module 4 around a current AUD off-ramp. Needs
research on what is actually available in Australia now.

### NOR-304 — replace it with a real AU offramp
The recommendation is now easy: **Coinbase Australia**. It was granted an AFSL with retail
derivatives authorisation by ASIC in early April 2026 — the first crypto exchange to receive one
directly from the regulator — days after the Corporations Amendment (Digital Assets Framework)
Bill 2025 passed both houses on 1 April 2026.

That makes it the strongest AU recommendation available, and it has the useful property of being
the same rails the rest of the stack already sits on: Base, Smart Wallet, x402. Module 4 becomes
a much simpler story.

Decide separately whether to pursue an affiliate angle at all, or just recommend plainly. Given
the trust-first positioning of the whole project, plainly is probably better.

## Closed 2026-08-11 — Module 4 rewritten around Coinbase Australia, affiliate claim removed

Aaron's direction: switch to Coinbase, add a do-your-own-research note, remove the affiliate stuff.

### What was actually wrong

Worse than "a dead link", which is how this issue was originally framed. Module 4 was *built around*
Stables — a "The Stables way: done in minutes" section, a five-step setup walkthrough, and line 55:

> *When you sign up through our link, you're supporting Carbon Contractors directly — we're a Stables
> affiliate partner.*

Nothing read `NEXT_PUBLIC_STABLES_AFFILIATE_URL`, so there was no link behind "our link" and no
affiliate relationship behind the claim. The site asserted a commercial relationship that did not
exist, with a provider that was winding down, on the single page answering the most practical question
an Australian worker has. For a project whose strategy is demonstrated honesty that is the worst place
on the site for it to have been.

### Changes

**`src/learn/module-4-spending-your-usdc-in-australia.md` — rewritten.**

- Recommends **Coinbase Australia**, on two stated grounds: it is the same rails the stack already
  runs on (Smart Wallet, Base), and it holds an AFSL granted directly by ASIC in April 2026.
- **Deliberately precise about what the AFSL means** — that it speaks to the entity's regulatory
  obligations, and is *not* a guarantee about any product, fee or feature. Overclaiming what a licence
  implies would repeat the exact sin this issue exists to fix.
- **No card product is recommended.** The honest route is exchange → sell → withdraw, and the module
  now says so up front rather than promising a tap-to-pay experience. The one genuine improvement
  worth stating is that the withdrawal leg is usually near-instant in Australia via PayID/Osko, not
  the 1–3 business days the old copy described.
- **New "Do your own research" section**, which is the part Aaron asked to emphasise. States plainly
  that this is not financial advice, that there is **no commercial relationship** with Coinbase or
  anyone else, and that if that ever changes it will be disclosed on the page in plain language. Then
  four specific things to verify: current fees from the provider's own pricing page; that the provider
  still operates as expected; the ATO position on disposal and on being paid in crypto; and never
  sending to an unverified address. It names the previous stale recommendation as the reason the page
  now says less and asks for more verification — publish-as-found applied to copy.
- **Added a USD-vs-AUD note.** USDC tracks the US dollar, so a rate quoted in USDC is effectively
  quoted in USD. This is the education half of `CC-024` (the `/connect` rate field still has no AUD
  context — that issue stays open for the form itself).

**`src/lib/learn/modules.ts`** — the Module 4 description was still the Stables pitch, *"Turn USDC
into spendable AUD in minutes with a Visa card. Tap and go at any terminal."* That string renders on
the `/learn` index, so it was as public as the module body. Replaced.

**`src/learn/module-6-dont-get-rekt.md:52`** — "your Stables account" → "your exchange account".

**`src/lib/config.ts`** — `NEXT_PUBLIC_STABLES_AFFILIATE_URL` removed from the Zod schema, with a
comment recording why and stating that there are deliberately no affiliate or referral vars, so a
future one has to be a conscious decision. **Aaron: remove it from the Vercel environment too** — it
is harmless there but it is the last trace.

`grep -rin "stables\|vield\|affiliate" src/ README.md` now returns only that explanatory comment.

### One change beyond the literal ask, flagged rather than done silently

The module also endorsed **Vield** as a self-custody alternative. That endorsement is gone. It is the
same defect class as Stables — an unverified third-party recommendation on a money page, carrying the
same staleness liability — and leaving it while removing the other would have been inconsistent. The
concept survives in the DYOR section ("self-custody spending options exist too… we're not going to
name providers we haven't verified"). If Vield should be named, put it back deliberately, with a note
on when it was last verified.
