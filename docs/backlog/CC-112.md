# CC-112 — Dashboard auto-signs on page load and the wallet picker fails silently

## Problem

Two related walkthrough failures in the connect/auth entry flow (found by the
PO click-through 2026-09-23, filed as NOR-342 and NOR-340):

1. **NOR-342 — the forced second login.** On dashboard load with no session
   cookie, `fetchWithSession`'s 401-retry path called `ensureSession()`, which
   calls `signMessageAsync` — from a mount effect, with no user gesture. For
   the Base Account connector that means a popup on page load, which mobile
   browsers and popup blockers refuse: the page half-loads, shows "This page
   couldn't load", and the user is stuck re-authenticating just to see a
   dashboard they already connected a wallet for.
2. **NOR-340 — the dead "Other Wallet" button.** The connector-picker branch
   of `WalletConnectButton` never rendered `useConnect()`'s `error`, and
   `injected()` on a browser with no `window.ethereum` rejects immediately.
   Net effect: on a clean browser profile the button does nothing visible.

## Fix

- `ensureSession` now probes `GET /api/auth/session` first (no prompt), and
  refuses to mint unless a user-gesture ref was set by an explicit click
  (`userGestureRef`). Mount effects never sign again.
- Dashboard load: probe → if live session, load everything silently; if not,
  render a "Sign in to see your work" button that owns the gesture and the
  single signature. `handleSignIn` reloads tasks/reputation/sessions after.
- `WalletConnectButton`: `connectWith` pre-checks `window.ethereum` for the
  injected connector and shows a plain-language install prompt; the picker and
  resume branches now also render the connect `error` itself.

## Acceptance

- [ ] Loading the dashboard with no session cookie produces **zero** wallet
  prompts; a single button click produces exactly one signature.
- [ ] A browser with no injected wallet shows guidance when "Other Wallet" is
  clicked, not silence.
- [ ] A failing connect attempt (any connector) surfaces its error message in the
  button component.

## Closed

Implemented on `fix/wallet-auth-lifecycle` (2026-09-24) — see PR for the diff
and test evidence.
