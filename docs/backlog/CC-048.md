# CC-048 — Self-hosted Sepolia node on the Z220

Migrated from NOR-280. Explicitly flagged as a future hyperfocus session, not mainnet
blocking. Repurpose the Z220 (headless Ubuntu) as a self-hosted Sepolia node to remove RPC
rate limits and add an independent cross-reference for KMS audit logs.

Storage is the constraint: archive needs roughly 1.5-2TB NVMe, pruned 200-400GB.
Geth + Lighthouse recommended for best first-timer docs, with Nethermind/Erigon and
Prysm/Teku as alternatives.

Four phases: baseline pruned node → Grafana/Prometheus monitoring → KMS audit feed
cross-reference → optional archive upgrade.

Security: RPC bound to local network only, no signing keys on the node, YubiKey-gated SSH.

Related: CC-040.

## Update 2026-07-30 — the rate limit is now costing something measurable

This was filed as a "future hyperfocus session" on the theory that public-RPC rate limits are an
inconvenience. They are currently making the **test suite non-deterministic.**

`.env.local` sets no `BASE_SEPOLIA_RPC_URL`, so `getChainConfig()`
(`src/lib/contracts/signer.ts:37-41`) falls back to `chain.rpcUrls.default.http[0]` —
`https://sepolia.base.org`. On 2026-07-30, five consecutive `npm test` runs on an unchanged tree gave
3 failures, then 1, then three clean runs of 74/74. The failing runs were the ones executed while
`scripts/audit/verify-contract-owner.mjs` was hitting the same endpoint.

So the immediate remedy is not a self-hosted node — it is stubbing the transport in tests
(`CC-060`) and setting `BASE_SEPOLIA_RPC_URL` to a dedicated provider endpoint. This issue stays P3;
it just now has a concrete cost attached rather than a hypothetical one.
