# CC-064 — Every Hardhat script is currently broken — Hardhat 3 requires ESM, this repo is CJS

## Problem

Discovered while dry-running a new script for `CC-059`. Any Hardhat invocation fails immediately:

```
npx hardhat run scripts/deploy/escrow.ts --network baseSepolia
```
```
Hardhat only supports ESM projects.

Please make sure you have "type": "module" in your package.json.
```

Reproduced with an *existing* script (`scripts/deploy/escrow.ts`), not just the new one — this is
not something introduced today. `package.json` resolves `hardhat` via `^3.2.0`, which is currently
sitting at `3.12.0` (`npm ls hardhat`). Hardhat 3 dropped CommonJS project support entirely; this
repo has no `"type": "module"` in `package.json` (defaults to CJS), and `tsconfig.hardhat.json`
explicitly targets `"module": "commonjs"`.

So right now: `npm run compile`, `npm run deploy:sepolia`, `npm run deploy:reputation`, the new
`npm run transfer:ownership` (`CC-059`), and any Hardhat test all fail identically. Nobody has run
a Hardhat script recently enough to have noticed — same pattern as `Lessons-Learned.md`'s repeated
theme of "it works because it was never re-run."

## Why the obvious fix isn't simple

Downgrading `hardhat` to a 2.x CJS-compatible version is not a clean option:
`hardhat-deploy@2.0.3`'s own `package.json` declares `"peerDependencies": { "hardhat": "^3.1.8" }` —
this repo's *other* Hardhat dependency was chosen assuming Hardhat 3. So the fix is the ESM
migration Hardhat's own error message points to, not a downgrade.

## Fix

1. Add `"type": "module"` to `package.json`.
2. Update `tsconfig.hardhat.json` to an ESM-compatible module setting (`"module": "esnext"` or
   `"nodenext"`, matching what Hardhat 3's own ESM-first tooling expects) and verify `hardhat.config.ts`
   still loads under it.
3. Re-check every other toolchain piece that reads `package.json`'s `type` field or assumes CJS:
   `vitest`, `tsx` (`npm run seed`, `npm run verify:kms`), `cross-env`. Next.js's own bundler is
   independent of this field and should be unaffected, but confirm with a full `npm run build`
   after the change, not just typecheck.
4. Re-run `npm run compile`, `npm run deploy:sepolia` (dry — or at least far enough to confirm the
   ESM error is gone before it needs a signer), and the new `npm run transfer:ownership` (dry run,
   no `--confirm`) to confirm all three actually execute now.

## Acceptance

`npx hardhat run scripts/deploy/escrow.ts --network baseSepolia` gets past the ESM check (fails
later for an unrelated, expected reason like a missing env var — not this error). `npm run build`
and `npx vitest run` still pass after the `"type": "module"` change.

Blocks the practical execution of `CC-059`'s ownership-transfer script (which was written and its
address-derivation logic independently verified, but could not be dry-run through the actual
Hardhat CLI because of this). Related: `CC-059`.
