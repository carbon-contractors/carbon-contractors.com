# CC-035 — Final security sweeps before mainnet

Section 5 of the MVP definition of done — the last gate.

Run an OWASP Top 10 web application sweep across the Next.js codebase, and a Web3 attack
vector sweep (OWASP Top 15 beyond smart contracts) across the whole project. Resolve every
CRITICAL and HIGH. Document MEDIUM findings as resolved or explicitly accepted with a
rationale. Attach the report for the audit trail.

Also re-run `npm audit` — 19 Dependabot alerts were cleared on 2026-05-09 and the tree has
been untouched since, so expect new ones after four months.

Aaron: this is a day-before-launch check for the *public* (testnet) launch, not something to wait
on until mainnet — a public site is a public attack surface regardless of which network the
escrow sits on. Re-scoped accordingly.

cleared the Dependabot/`npm audit` backlog once this session; this issue's `npm audit` re-run
should be the *last* thing done before go-live, not a duplicate of that pass.

This will need running again before mainnet regardless — new dependencies, new time elapsed, and
a different (real-money) risk profile all justify a second pass. Not filing that as a separate
issue now; note it here so it isn't missed when `CC-039` (mainnet hub) is picked up.

## Update 2026-08-11 — backlog triage pass

Closed as **`wontfix`** — converted to a checklist line rather than tracked as an issue.

**Reason:** this is not a defect. It is a launch-day procedure, and this issue said so itself: run it
*immediately before* flipping the gate, because a sweep run now would be stale by the time the gate
actually lifts. Carrying it as an open P0 meant the P0 list mixed "work on this" with "remember to do
this on the day", which made the board harder to read rather than safer.

It now appears as an explicit gate line in both `CC-076` (Sepolia validation) and `CC-039`
(mainnet), which is where the sequencing actually lives. Nothing about the scope is dropped — the
OWASP Top 10 sweep, the Web3 attack-vector sweep, resolving every CRITICAL and HIGH, documenting
accepted MEDIUMs, and the final `npm audit` re-run all survive as checklist items, in both places,
because both milestones need their own pass.

Note for whoever runs it: parts of `CC-045`'s checklist are not npm-specific and are worth folding
into this sweep — the `child_process`/`exec`/`spawn`/`eval` audit and Zod coverage on every
MCP tool input apply to the already-live `/api/basedhuman.mcp` endpoint.
