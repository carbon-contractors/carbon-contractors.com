# CC-047 — Migrate git commit signing from SSH to GPG on YubiKey

Migrated from NOR-302.

Generate a GPG key on the YubiKey (prefer generate-on-device so it is non-exportable),
configure git global signing and auto-sign, add the public key to GitHub, confirm the
Verified badge appears, update the WSL config separately from Windows native, record the key
id in Bitwarden, and confirm the Ledger Nano X is still enrolled as backup.

## Note
The three commits made on 2026-07-25 (`.gitattributes`, backlog tracker, this import) are
**unsigned** — they were made with explicit `-c user.name`/`-c user.email` rather than your
global config. If you enforce signing, they will show as unverified.

## Hardware-swap note
See CC-053. If the current SSH signing key lived in a TPM-backed store or behind Windows
Hello, the motherboard swap destroyed it. A YubiKey-resident key would have survived — which
is the argument for this issue.

Related: CC-053, CC-041.

## Update 2026-08-10 — done, via SSH-SK rather than GPG

Aaron flagged this was already achieved; verified directly rather than taken on say-so:

```
git config --get gpg.format        → ssh
git config --get user.signingkey   → C:/Users/aaron/.ssh/id_ed25519_sk_signing
git log --show-signature -3        → "Good "git" signature for ...
                                       with ED25519-SK key SHA256:cvlxwU..."
```

The `-sk` suffix means this is a FIDO2/security-key-backed SSH key — hardware-resident,
non-exportable, requires physical touch to sign (confirmed live, repeatedly, over this same
session's commits — the "Confirm user presence for key ED25519-SK" prompts). That is the actual
goal this issue existed for: hardware-backed signing that can't be exfiltrated. It was specified
as a GPG migration because that was the conventional path at the time; SSH signing achieves the
identical security property and is what's actually configured and working.

Not done: adding the public key to GitHub / confirming the Verified badge on a *direct* push
(this repo's branch protection means every commit currently lands via a PR merge, which GitHub
signs itself with its own key — see the `gpg: ... using RSA key ... Can't check signature` line
on merge commits, unrelated to this setup). Worth a quick check next time signing comes up, not
worth reopening this issue for.

**Closed.**
