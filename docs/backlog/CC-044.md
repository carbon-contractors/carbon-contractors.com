# CC-044 — Build the standalone basedhuman-mcp server package

Migrated from NOR-300. A distributable MCP server, separate from the Next.js route that
serves `/api/basedhuman.mcp` today.

## Tools
`listTasks`, `getTask`, `submitBid`, `completeTask`, `getAgentStatus`.
`completeTask` **must** read the contractor wallet from on-chain escrow state, never from
Supabase — see CC-037.

## Decisions still open
STDIO vs HTTP/SSE transport; challenge-response auth reusing the NOR-178 pattern already in
`src/app/api/basedhuman.mcp/route.ts`; Zod validation on every input; x402 integration.

Blocked by CC-045 — do not publish to npm beyond a name reservation until the supply-chain
hardening is done.

Related: CC-045, CC-046.

## Update 2026-08-11 — backlog triage pass

Lowered P1 → **P2**, and re-scoped to distribution only.

**Why the 2026-08-10 reasoning does not hold.** That update reclassified this to `public-launch` on
the basis that agents cannot discover the platform without it. Re-checked during the triage pass, and
that is not the case: the *in-app* MCP server is real, live, and reachable by agents today —
`src/lib/mcp/server.ts` is 1,089 lines with ten `server.tool()` registrations, served by
`src/app/api/basedhuman.mcp/route.ts` (193 lines, plus a `challenge/` sub-route), and `/api/*`
bypasses the coming-soon gate. Confirmed directly: the triage session had this server connected as an
MCP client and could enumerate all ten tools. So an agent can connect over HTTP right now by pointing
at the URL.

What is missing is the ergonomic packaging — an npm-installable STDIO wrapper so an agent operator
does not have to hand-configure an HTTP endpoint. That is real work and worth doing, but it is
adoption polish, not a prerequisite, and it does **not** gate the lifecycle testing in
`CC-032`/`CC-077`/`CC-078`/`CC-079`.

**This issue's tool list is fiction and must be rewritten before any work starts.** It specifies
`listTasks`, `getTask`, `submitBid`, `completeTask`, `getAgentStatus` — inherited verbatim
from NOR-300 and never reconciled against what was actually built. The ten real tools are
`search_whitepages`, `request_human_work`, `get_task_status`, `confirm_task_completion`,
`register_notification_channel`, `get_contractor`, `list_categories`, `get_reputation`,
`dispute_task`, `resolve_dispute`. There is no `submitBid` concept anywhere in the product.

**Flagged for Aaron, deliberately not done:** the consistent follow-through on this reclassification
is moving this issue back to `epic: mcp-package`, which would also drop it out of `CC-076`'s gate
list. Left as `public-launch` because that epic was set by an explicit decision on 2026-08-10 and
reversing it is Aaron's call, not a tidy-up.
