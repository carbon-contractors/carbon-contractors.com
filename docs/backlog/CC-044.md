# CC-044 — Build the standalone basedhuman-mcp server package

Migrated from NOR-300. A distributable MCP server, separate from the Next.js route that
serves `/api/basedhuman.mcp` today.

## Tools
`listTasks`, `getTask`, `submitBid`, `completeTask`, `getAgentStatus`.
`completeTask` **must** read the contractor wallet from on-chain escrow state, never from
Supabase — see CC-037.

## Decisions still open
STDIO vs HTTP/SSE transport; challenge-response auth reusing the NOR-178 pattern already in
`src/app/api/basedhuman.mcp/route.ts`; Zod validation on every input; x402 integration.

Blocked by CC-045 — do not publish to npm beyond a name reservation until the supply-chain
hardening is done.

Related: CC-045, CC-046.

## Update 2026-08-10 — reclassified: public-launch (was mcp-package)

Checked what's actually in the `basedhuman-mcp` GitHub repo (a placeholder, per Aaron — confirmed:
just a `LICENSE`, `README`, and a 3-line `index.js` that prints a pointer to
`carbon-contractors.com/api/basedhuman.mcp`). The live website's own MCP endpoint already works
today and isn't gated on this issue — I'd initially read this as a later, separate distribution
concern for exactly that reason.

Aaron's correction: this is core to how agents *discover* the platform, not just a technical nice-
to-have, and it needs to be built and tested **while still on Sepolia** — proving the standalone
package's tool surface (`listTasks`, `getTask`, `submitBid`, `completeTask`, `getAgentStatus`)
works correctly is far cheaper to get wrong against testnet than against mainnet later. Reclassified
accordingly.

Still blocked by `CC-045` for anything beyond the current name-reservation placeholder — do not
publish real functionality to npm until that supply-chain hardening is done.
