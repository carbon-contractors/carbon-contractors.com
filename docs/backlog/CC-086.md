# CC-086 — Kill switch on task creation

Specified by `ADR-0003` D4. A launch prerequisite that was not previously tracked anywhere.

## Why

`CC-040` already asks for a runbook per alert type. Post-ADR the correct first response to most
invariant violations is **not to debug — it is to stop new task creation** while the money path is
in an unknown state. Existing tasks resolve safely on their own clocks; new ones would not.

That means the runbooks have no valid first step until this exists.

## The critical constraint

**Pause intake, never disbursement.** This must not pause *claims*. Halting settlement while tasks
are in flight would strand funds and invert the whole `ADR-0001` D6 position — the liveness default
exists precisely so that platform inaction cannot decide an outcome.

## Scope

- A switch that stops new task creation and is **independent of the site being up**.
- Per-invariant runbooks (`CC-085`), each beginning with the pause step where appropriate.

## Open

From `ADR-0003`: whether the switch is contract-level (pause `createTask`) or app-level (refuse
`request_human_work`). Contract-level is stronger and survives an app compromise; app-level is
reversible without a transaction. Probably both, at different tiers — which makes it a `CC-082`
consideration if the contract-level half is wanted in the same redeploy.
