# CC-086 — Kill switch on task creation

Specified by `ADR-0003` D4. A launch prerequisite that was not previously tracked anywhere.

## Why

`CC-040` already asks for a runbook per alert type. Post-ADR the correct first response to most
invariant violations is **not to debug — it is to stop new task creation** while the money path is
in an unknown state. Existing tasks resolve safely on their own clocks; new ones would not.

That means the runbooks have no valid first step until this exists.

## The critical constraint

**Pause intake, never disbursement.** This must not pause *claims*. Halting settlement while tasks
are in flight would strand funds and invert the whole `ADR-0001` D6 position — the liveness default
exists precisely so that platform inaction cannot decide an outcome.

## Scope & Implementation

- **Intake Freeze Switch:** `NEXT_PUBLIC_INTAKE_PAUSED=true` / `NEXT_PUBLIC_INTAKE_PAUSE_NOTICE` in `src/lib/config.ts`.
- **MCP Rejection:** `request_human_work` (`src/lib/mcp/server.ts`) refuses new tasks with informative payload (`intake_paused: true`, `claims_active: true`, `retry_after_s: 300`) while keeping whitepages, reputation, and settlement tools unblocked.
- **Frontend Banner:** `<IntakePauseBanner />` in `src/components/PageShell.tsx` renders a high-visibility emergency notice across all pages reassuring workers that claims and active settlements are unaffected.
- **Emergency Multi-Channel Broadcast:** `scripts/emergency-broadcast.mjs` dispatches rich embeds to Discord webhooks (`MONITOR_WEBHOOK_URL`) on pause and resumption.
- **Per-Invariant Runbooks:** `docs/runbooks/INVARIANT-ALERTS.md` details immediate step 1 pause procedure, diagnostic checklists per invariant monitor (`verify-escrow-solvency`, `verify-contract-owner`, `verify-signer`, `verify-unclaimed`), and recovery protocol.
