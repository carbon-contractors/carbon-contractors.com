# CC-039 — Mainnet go-live gate checklist (hub)

Migrated from NOR-306, which was the hub issue — nearly every other open Linear issue fed
into it. Treat this as the mainnet readiness source of truth and keep it current.

## Gates
**Prerequisite** — `CC-076` (Sepolia validation gate) must be done before any of the below
starts. `CC-034` already said this explicitly ("do not start until CC-032 and CC-035 are green")
before this issue existed to make it structural.
**Contract** — deploy to Base mainnet, Slither scan, Basescan verify (CC-034)
**Security (mainnet-specific), day-of** — run the full OWASP Top 10 web sweep and the Web3
attack-vector sweep across the project, resolve every CRITICAL and HIGH, document MEDIUMs as
resolved or explicitly accepted with a rationale, attach the report for the audit trail, and re-run
`npm audit`. Run this *immediately before* the mainnet cutover, not in advance — a sweep goes stale
as soon as anything else changes. Do not assume the Sepolia pass still holds after however long the
site has been sitting behind the coming-soon gate on testnet, and note the risk profile is different
now that the money is real. (This was tracked as `CC-035`, closed `wontfix` on 2026-08-11 because it
is a launch-day procedure rather than a defect; the scope lives here and in `CC-076`.) Fold in the
non-npm-specific items from `CC-045` while you are here: the
`child_process`/`exec`/`spawn`/`eval` audit and Zod coverage on every MCP tool input.
**Infrastructure** — Cloudflare WAF review, Vercel env var audit (repoint every `NEXT_PUBLIC_*`
contract address and network var to mainnet)
**Content / business** — Security-Trust-Disclosure.md current for mainnet, confirm /learn and
the homepage no longer carry testnet-specific language once real money is live
**Smoke test (mainnet, with real funds)** — full fund → complete → pay lifecycle, plus dispute
flow, run by Aaron with his own money before anyone else's. This is the "re-test everything with
my own funds" step, and nothing after it is allowed to assume the Sepolia results still hold.
**Public launch** — `CC-014` (flip `NEXT_PUBLIC_COMING_SOON`, redeploy, verify). This is the
literal last gate in the whole backlog: it does not run until the mainnet smoke test above is
clean. The public sees the site for the first time here, on mainnet, not on Sepolia.
**Post go-live** — 48-hour watch checks

## Update 2026-08-10 — split from the Sepolia validation gate

This hub had been carrying gates for two different milestones — everything provable on Sepolia,
and moving to Base mainnet — which made it unclear which items were actually blocking the *next*
thing. Moved everything that's really about Sepolia validation (`CC-041`, `CC-032`, `CC-040`,
`CC-029`, `CC-007`, plus several found and reclassified this session — `CC-035`, `CC-037`,
`CC-044`, `CC-045`, `CC-046`, `CC-036`) out to the new `CC-076`. What remains here is genuinely
mainnet-only: things that cannot happen, or cannot be meaningfully verified, before a mainnet
deployment exists at all. `CC-043`, `CC-042`, `CC-049` were already `done` and are removed from
the active gate list rather than left as stale references.

## Update 2026-08-10 (2) — the coming-soon gate flip belongs here, not in CC-076

Aaron confirmed the actual sequence explicitly: build and test everything on Sepolia first (`CC-076`)
→ switch to mainnet and re-test the full lifecycle with real personal funds (this issue) → only
once that's clean does the site open to the public. `CC-014` (the coming-soon gate flip) had been
listed as `CC-076`'s last step, which implied the public sees the site while still on Sepolia.
That's backwards from Aaron's stated plan — moved `CC-014` here as the final gate, run only after
the mainnet smoke test above passes. `CC-076` finishing means "ready to attempt mainnet," not
"ready to go public."
