# CC-016 — No way to read the waitlist from the app

Only `ComingSoon.tsx` and the POST route touch `waitlist`, and migration
`010_drop_anon_read_pii.sql` removed anon SELECT. Reading signups means opening the Supabase
dashboard.

Fix: either accept the Supabase dashboard as the workflow and close this, or add a protected
`/api/admin/waitlist` behind wallet-signature auth restricted to the owner address.

---

## Update 2026-08-11 — backlog triage pass

Closed as **`wontfix`** — the Supabase dashboard is accepted as the workflow for reading
the waitlist. This issue offered that as an explicit valid outcome and Aaron chose it during the
triage pass.

**Reason, stated for the record:** building `/api/admin/waitlist` would add another
authenticated surface over real third-party PII, for a task performed rarely and already possible
through a tool with its own access controls and audit trail. The dashboard is the lower-risk option,
not merely the lazier one. `CC-062` (revoking the default anon grants on `waitlist`) is the work
that actually protects those addresses, and it is being done.

Revisit only if the list grows large enough that acting on it in bulk needs app support.
