# CC-076 — Public launch go-live gate checklist (hub)

## Why this exists

`CC-039` ("Mainnet go-live gate checklist") had been doing double duty as the checklist for two
different milestones: opening the coming-soon gate to the public on Sepolia (soon), and moving to
Base mainnet with real money (later, separately gated). That made it hard to tell which items
were actually blocking the *next* thing versus a later one — `CC-034` (mainnet deploy) already
says "do not start until CC-032 and CC-035 are green," which is exactly the public-launch/mainnet
split this issue makes explicit.

This is that split: the hub for "can we flip `NEXT_PUBLIC_COMING_SOON` to `false` in Production."
`CC-039` is now scoped to mainnet only, and gates on this issue being done first.

As with `CC-039`, do not trust inherited tick-boxes — re-derive each gate's status from the code
and the backlog before treating anything here as authoritative, this list included.

## Gates

**Security**
- `CC-035` — OWASP Top 10 + Web3 sweep, `npm audit` re-run. Run last, day-of.
- `CC-037` — re-verify the escrow trust boundary against current code (fund-safety invariants).
- `CC-041` — YubiKey-only 2FA enforced on the GCP project holding the KMS/HSM key.

**Correctness / fund safety**
- `CC-032` — Sepolia end-to-end lifecycle test (happy path, unhappy paths, edge cases).
- `CC-070` — `eth_getLogs` queries exceeding the public RPC's block-range limit (affects
  reputation display and `CC-065`'s dispute-recovery path).
- `CC-072` — the on-chain staking flow has never been executed once, end to end.

**Content / trust**
- `CC-007` — site copy promises real USDC earnings while running on testnet.
- `CC-029` — Stables (dead) → Coinbase Australia in Module 4.
- `CC-036` — task completion attestations; currently described as live in the homepage/Learn
  copy but not built. Ship the feature, or the copy needs the caveat removed only once it's real.

**Infrastructure**
- `CC-040` — error alerting, on-chain event monitoring, uptime, runbook. Partially covered by
  Vercel Pro / Supabase Pro already; the rest is a day-before-launch task, same sequencing as
  `CC-035`.
- `CC-014` — the actual launch runbook (redeploy required, not just an env var flip). This is the
  literal last step.

**Agent-facing / MCP**
- `CC-044` — build and test the standalone `basedhuman-mcp` package against Sepolia, not deferred
  post-launch. Core to how agents discover the platform, not just a distribution nice-to-have.
- `CC-045` — supply-chain and STDIO hardening, blocks any real npm publish of `CC-044`.
- `CC-046` — MCP idempotency/retry semantics for the *already-live* `/api/basedhuman.mcp`
  endpoint — proposed for this hub, not yet explicitly confirmed; flagging rather than assuming.

**Smoke test**
Full register → discover (MCP) → x402 fund → notify → deliverable → `confirm_task_completion` →
payout cycle, plus the dispute → `resolve_dispute` path, run against the live Production Sepolia
deployment immediately before flipping the gate — not a staging/preview run.
