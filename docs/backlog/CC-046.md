# CC-046 — MCP production readiness: idempotency, pre-set params, retry semantics

Migrated from NOR-294. The MCP spec deliberately says nothing about retries or failure
handling, so every server has to define its own. With money attached, "the agent retried and
we paid twice" is the failure that matters.

## Scope
- **Pre-set params** — chain ID, escrow address, USDC address and RPC URL become config-time
  constants rather than agent-supplied arguments. This alone kills the lookalike-token
  vector, where an agent passes a malicious USDC address.
- **Idempotency** — `createTask`, `fundEscrow` and `completeTask` all idempotent via
  idempotency keys, with TTL, stored in Supabase or the existing Upstash instance
- **Retry / failure semantics** — structured `{ retryable, reason, code }` errors,
  exponential backoff guidance, pending-transaction polling
- **Observability** — structured logs with correlation IDs, no PII or secrets (see CC-009)
- **Tool surface governance** — one source of truth, versioned schema

Progressive tool discovery is noted as low priority while the tool count stays under 10.

Related: CC-044, CC-045, CC-009.
