# CC-046 — MCP production readiness: idempotency, pre-set params, retry semantics

Migrated from NOR-294. The MCP spec deliberately says nothing about retries or failure
handling, so every server has to define its own. With money attached, "the agent retried and
we paid twice" is the failure that matters.

## Scope
- **Pre-set params** — chain ID, escrow address, USDC address and RPC URL become config-time
  constants rather than agent-supplied arguments. This alone kills the lookalike-token
  vector, where an agent passes a malicious USDC address.
- **Idempotency** — `createTask`, `fundEscrow` and `completeTask` all idempotent via
  idempotency keys, with TTL, stored in Supabase or the existing Upstash instance
- **Retry / failure semantics** — structured `{ retryable, reason, code }` errors,
  exponential backoff guidance, pending-transaction polling
- **Observability** — structured logs with correlation IDs, no PII or secrets (see CC-009)
- **Tool surface governance** — one source of truth, versioned schema

Progressive tool discovery is noted as low priority while the tool count stays under 10.

Related: CC-044, CC-045, CC-009.

## Update 2026-08-23 — done

Implemented on `feat/cc-046-mcp-production-readiness` (PR follows this commit). Scope delivered,
against the ticket's three core items:

- **Pre-set params** — verified and now *enforced by test* (`mcp-preset-params.test.ts`): no MCP
  tool accepts chain id, escrow address, USDC address or RPC URL as an argument; they are
  config-time constants (`getEscrowConfig`, `src/lib/config.ts`). This was already true by
  construction; the test stops a regression. Smuggled values are dropped by the handler before
  reaching the task-creation call.
- **Idempotency** — `request_human_work` gains an optional caller-scoped `idempotency_key`
  (1–128 chars). A retry with the same key inside a 24h TTL returns the original task's full
  funding parameters (`idempotent_replay: true`) instead of creating a second row — checked
  *before* the rate limiter and *before* worker notification, so a replay costs nothing.
  Migration `020` adds `tasks.idempotency_key` plus a partial unique index on
  `(from_agent_wallet, idempotency_key)` as the race backstop: a concurrent duplicate insert
  fails `23505` and the loser replays the winner's row from the catch, so "the agent retried and
  we paid twice" is closed at both the lookup and the insert. Also stores
  `tasks.review_window_seconds` so a replay can reconstruct the full v2 `createTask` parameter
  set from the row alone.
- **Retry/failure semantics** — every tool error now carries
  `{ ok: false, error, code, retryable, reason? }` via `src/lib/mcp/errors.ts` (19 stable codes;
  `retryable` defaults per code, overridable). Human-readable messages are unchanged, so
  existing consumers keep working.

**Honest scope notes:**

- Idempotency keys cover `request_human_work` only. The ticket named `createTask`/`fundEscrow`/
  `completeTask` too — but after `CC-080`/`CC-092` the platform no longer transacts anywhere in
  settlement: the agent funds and settles from its own wallet, and Ethereum transactions are
  idempotent by nonce. The one platform-side money write left (`resolve_dispute`) already had
  its own partial-failure recovery (chain-first check). The task-creation tool is the only
  remaining place a *retry* could double-create.
- Storage is the `tasks` table (service role), not Upstash — there is no live Upstash instance,
  and the unique-index backstop needs the DB anyway.
- Observability/correlation IDs and tool-surface versioning: structured `log()` events exist at
  every new seam (`request_human_work_idempotent_replay`, `_race_replay`, `_failed`); a full
  correlation-ID plumbing pass and schema versioning were not built and are not blocking.

Tests: `mcp-idempotency.test.ts` (9), `mcp-error-semantics.test.ts` (9),
`mcp-preset-params.test.ts` (2), plus extensions to `mcp-request-human-work.test.ts`,
`tasks.test.ts` and `x402.test.ts`. `npm test` 578/578, `npm run typecheck`, `npm run lint`
(pre-existing warning in `basedhuman.mcp/route.ts` only) and `npm run build` all green.
