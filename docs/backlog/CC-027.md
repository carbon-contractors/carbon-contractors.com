# CC-027 — README claims Zero PII while the app stores email addresses

`README.md` design constraints state "**Zero PII** — no personal data stored, ever. Wallets
and skills only." The `waitlist` table stores email addresses, `notification_channels` is
explicitly a PII table in the architecture doc, and CC-005 proposes collecting contact
details at signup.

This is a public repo and the claim is quotable. Fix: restate honestly — minimal PII, only
what is needed to notify you, never exposed to agents — and align it with the privacy policy
from CC-008.

## Update 2026-08-11 — backlog triage pass

Raised P3 → **P1**. Verified `README.md:173` still reads "**Zero PII** — no personal
data stored, ever. Wallets and service categories only."

The reason this is no longer a P3 docs nit: `CC-008` has since shipped a privacy policy that
*describes* collecting email addresses. So the public repo now contradicts its own published legal
page. For a project whose trust strategy is demonstrated honesty, a quotable false claim sitting
next to a contradicting legal document is worse than the original inaccuracy was on its own.

One-paragraph fix — restate as minimal PII, only what is needed to notify a worker, never exposed to
agents — and align the wording with the privacy policy rather than inventing a third version.
