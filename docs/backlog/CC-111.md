# CC-111 — Independent external uptime monitor (PO action)

Split out of `CC-040` at its closure. Two things the repo cannot do for itself; both
require credentials only the PO can create. Everything else in `CC-040`'s operational
half shipped in its closing PR.

## Why this needs a human

`ADR-0003` D5 requires **two independent alerting paths** for uptime, because a monitor
hosted on GitHub cannot report that GitHub is the thing that failed — the same
reasoning that already backs the dead-man's switch for the invariant monitors. The
repo-side half is done (`verify-uptime` in the hourly schedule, `CC-040`). The
independent half needs an account on a service the repo does not control, so it is a
PO action in the same shape as `CC-109` (R2 bucket provisioning).

## Scope

1. **External uptime check.** A free-tier account on one of: healthchecks.io,
   UptimeRobot, BetterStack, Cronitor. Configure it to check
   `https://www.carbon-contractors.com/api/health` (HTTP 200 expected; the route
   returns 503 when a subsystem is unhealthy, which the checker should treat as down).
   Frequency 5–15 min is fine on every free tier. Point its alerts at the same channel
   the `MONITOR_WEBHOOK_URL` Discord/Telegram alerts arrive on, or a channel that
   reaches the PO directly — that is the point of independence.
2. **Optionally, a second dead-man's switch for verify-uptime specifically.** The
   existing `MONITOR_HEARTBEAT_URL` covers the whole monitor run; if the external
   service supports cron monitors (healthchecks.io does), a dedicated ping for the
   uptime monitor adds nothing the shared one does not already cover — skip unless the
   chosen service makes it trivial.
3. **Alert destination for application errors.** `src/instrumentation.ts` (CC-040)
   relays uncaught request errors to `MONITOR_WEBHOOK_URL`. That value is currently a
   **GitHub repo secret only** — the Vercel deployment does not have it, so the relay
   runs in log-only mode in production until the PO sets it as a Vercel environment
   variable:
   ```bash
   # one-time, or via the Vercel dashboard → Settings → Environment Variables
   vercel env add MONITOR_WEBHOOK_URL production
   ```
   (Value is the same Discord/Telegram webhook URL already stored as the GitHub
   `MONITOR_WEBHOOK_URL` secret. It is a bearer credential — do not put it in the repo.)

## Acceptance

- [ ] External uptime checker configured against the production health URL, alerting
      a channel the PO actually reads
- [ ] `MONITOR_WEBHOOK_URL` set in the Vercel production environment; a forced error
      (e.g. hitting an API route that throws in a preview deployment) produces a
      webhook alert
