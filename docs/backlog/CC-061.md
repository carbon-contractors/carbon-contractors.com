# CC-061 — Dependency advisories, and the CI audit gate now fails

## Problem

`npm audit` on 2026-07-30, after a clean `npm ci`:

```
56 vulnerabilities (3 low, 34 moderate, 17 high, 2 critical)
npm audit --audit-level=high   ->   exit 1
```

`.github/workflows/ci.yml:29` runs `npm audit --audit-level=high`, so **CI fails at the audit step
on the next push to `master`.** Everything else is clean: `lint` exit 0 (31 warnings, 0 errors),
`typecheck` exit 0, `build` exit 0, tests 74 passing (see `CC-060` for their flakiness).

CI is not red today — it is *idle*. The last run on `master` was 2026-05-09 (success); nothing has
pushed to `master` in 82 days. GitHub's Dependabot view shows 76 open alerts (1 critical, 28 high,
42 medium, 5 low); it counts per-alert where `npm audit` counts per-package.

Accepted deliberately: the 12 commits of 2026-07-25/30 are being pushed before this is fixed, so
the first public CI run will be red. Publishing a red build is a more honest signal than holding
the work on one machine. Fix follows immediately after.

## The two criticals

Both are `vitest` — GHSA-5xrq-8626-4rwp, arbitrary file read and execution when the Vitest UI
server is listening. Dev-only, and the UI server is not used here. Fix is non-major:
`vitest >=3.2.6` plus `@vitest/coverage-v8`.

## The high-severity ones that matter

**`next` 16.2.6 carries 9 advisories, fixed in 16.2.12 — a non-major bump.** Two are directly
relevant to this application:

- **GHSA-6gpp-xcg3-4w24** — middleware/proxy bypass in App Router. `middleware.ts` is the entire
  coming-soon gate. Worth confirming whether the Turbopack + single-locale precondition applies
  here before assuming exposure, but this is the one to read first.
- **GHSA-q8wf-6r8g-63ch** — denial of service in the Image Optimization API via SVG. **This answers
  `CC-042`: the Next.js DoS advisory is not closed.**

Also: GHSA-955p-x3mx-jcvp (unauthenticated disclosure of internal Server Function endpoints),
GHSA-89xv-2m56-2m9x (SSRF in Server Actions), GHSA-68g3-v927-f742 and GHSA-4633-3j49-mh5q (cache
confusion). `postcss` and `sharp` resolve via the same bump.

Transitive leaves, all with fixes available: `@grpc/grpc-js`, `axios` (10 advisories), `hono` (12),
`protobufjs` (11), `brace-expansion`, `fast-uri`, `form-data`, `js-yaml`, `undici`, `vite`.

## The two awkward ones

- **`ws` → wants `wagmi` 3.x, a semver major.** `CC-043` already plans to drop OnchainKit for
  explicit wagmi + viem. **Do these together** — bumping wagmi twice would mean re-testing the
  wallet path twice, and the wallet path is the one thing that has never been properly tested
  (`CC-055`).
- **`hardhat` / `hardhat-deploy` / `adm-zip`** — `npm audit` proposes `hardhat@0.0.7`, which is
  nonsense; its resolver is confused. Dev-only, used for contract compilation, never shipped.
  Likely needs manual version selection or an override.

## The `overrides` block is stale

`package.json:55-63` pins `protobufjs >=7.5.5` while the tree resolves 8.x, and `vite >=6.4.2 <7`
while the advisory covers `<=6.4.2`. These overrides were added to silence earlier audits and now
silence nothing. Re-derive them rather than nudging the numbers.

## Fix

1. Non-major first, and measure the effect: `next@16.2.12`, `vitest`/`@vitest/coverage-v8`, then
   refresh the `overrides` block for the transitive leaves.
2. Re-run `npm audit --audit-level=high` and see what is left.
3. Fold the `wagmi`/`ws` chain into `CC-043` rather than doing it standalone.
4. Handle `hardhat` separately; it is dev-only and should not gate a launch.
5. Close `CC-042` once the Next bump lands and the advisory is confirmed absent.

## Acceptance

`npm audit --audit-level=high` exits 0, and CI is green on `master`.

Related: `CC-042`, `CC-043`, `CC-060`.
