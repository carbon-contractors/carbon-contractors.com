# CC-113 — Staking panel swallows contract-write failures and never shows the wallet's USDC balance

## Problem

The walkthrough hit a real chain failure and the UI hid every trace of it
(NOR-346), then stranded the panel (NOR-345), and the same silent-failure
disease affected the wallet disconnect button (NOR-348):

1. **NOR-346 — staking failed with no explanation.** The Base Account's
   UserOperation simulation failed: "Failed to estimate gas for user operation:
   insufficient balance to perform useroperation: ERC20: transfer amount exceeds
   balance" — the USDC sat in a different wallet than the one connected. The
   panel never showed the connected wallet's USDC balance, so the mistake was
   unmakeable-in-theory, and when the bundler refused, nothing rendered.
2. **NOR-345 — stuck "Staking…".** Nothing in `dashboard/page.tsx` read
   `useWriteContract`'s `error` or the receipt's `isError`. Any rejected
   signature, failed simulation or reverted tx left `stakeStep` parked, the
   inputs disabled, and the dashboard stale — the disconnect button appeared
   dead in this state too (NOR-348's report).
3. **NOR-348 — disconnect swallows errors.** `disconnect()` failures were
   unhandled; the button looked dead with no message.

## Fix

- `reverts.ts`: new `MESSAGE_MATCHERS` — sentence-level translation for
  ERC-4337 bundler and OpenZeppelin ERC-20 failures that never arrive as
  `Name(...)` decodes. The ERC-20 needle is checked first so "transfer amount
  exceeds balance" wins over the generic user-operation phrasing. Extend
  `explainContractError` to consult it before the fallback.
- Dashboard: read `writeContractError` / receipt `isError`; every failure
  path resets `stakeStep` and shows a translated sentence via
  `explainContractError`. Successful confirmation clears the error.
- Balance preflight: read-only `useBalance` on the connected wallet's USDC;
  the panel shows the balance, and `handleStake` refuses to request a
  signature the balance cannot cover.
- `WalletConnectButton`: `disconnect()` wrapped — a throwing connector now
  gets a visible note instead of silence.

## Acceptance

- [ ] A failed stake attempt (any cause) shows a human sentence, resets the
  buttons, and re-enables input.
- [x] The bundler's underfunded-UserOperation error specifically renders as the
  "wrong wallet / not enough USDC" translation (unit-tested).
- [ ] The panel displays the connected wallet's live USDC balance, and an
  over-balance stake amount is blocked before any signature prompt.
- [ ] A disconnect failure shows a message rather than nothing.
