# CC-045 — MCP supply chain and STDIO hardening before publishing

Migrated from NOR-293. Written in response to the reported MCP STDIO design flaw affecting
roughly 200k servers with 10+ CVEs. Blocks any npm publish of CC-044.

## Four vulnerability classes to check
Command injection; argument-injection bypass of the hardening; zero-click prompt injection
via a poisoned MCP config; marketplace poisoning.

## Checklist
- **Code audit** — grep for `child_process`, `exec`, `spawn`, `eval`; Zod validation on every
  tool input with no unvalidated passthrough
- **Supply chain** — npm 2FA via YubiKey, publish with GitHub Actions OIDC provenance,
  `npm audit signatures`, Dependabot on the package repo, tight `.npmignore` scope
- **Consumer guidance** — README steps for verifying provenance, SECURITY.md update

## Defence in depth
Because `completeTask()` takes the payout address from on-chain escrow state, a compromised
MCP config cannot redirect funds — it can only lie about task metadata. That property is
load-bearing for this whole threat model, which is why CC-037 needs confirming first.

Related: CC-037, CC-044, CC-046.
