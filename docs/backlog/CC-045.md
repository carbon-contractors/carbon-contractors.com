# CC-045 — MCP supply chain and STDIO hardening before publishing

Migrated from NOR-293. Written in response to the reported MCP STDIO design flaw affecting
roughly 200k servers with 10+ CVEs. Blocks any npm publish of CC-044.

## Four vulnerability classes to check
Command injection; argument-injection bypass of the hardening; zero-click prompt injection
via a poisoned MCP config; marketplace poisoning.

## Checklist
- **Code audit** — grep for `child_process`, `exec`, `spawn`, `eval`; Zod validation on every
  tool input with no unvalidated passthrough
- **Supply chain** — npm 2FA via YubiKey, publish with GitHub Actions OIDC provenance,
  `npm audit signatures`, Dependabot on the package repo, tight `.npmignore` scope
- **Consumer guidance** — README steps for verifying provenance, SECURITY.md update

## Defence in depth
Because `completeTask()` takes the payout address from on-chain escrow state, a compromised
MCP config cannot redirect funds — it can only lie about task metadata. That property is
load-bearing for this whole threat model, which is why CC-037 needs confirming first.

Related: CC-037, CC-044, CC-046.

### Verification

- `mcp-register-channel.test.ts` (15 tests): unauthenticated rejection; channel bound to
  caller's contractor record with smuggled `contractor_id` ignored; schema no longer exposes
  `contractor_id`; unregistered-caller rejection; six invalid-address rejections (http
  webhook, non-URL, @username telegram, alphanumeric telegram, #tag discord, malformed email);
  four valid per-type registrations with normalisation; no address echo in responses.
- Full gates: `npm test` 813/813, `npm run typecheck`, `npm run lint` (0 problems),
  `npm run build` — all green on `fix/cc-045-mcp-hardening`.
- Consumer surfaces updated to match: `/mcp-info` page params; SECURITY.md gains the audit
  section and corrects the NOR-174 closure record.

### npm publish gate (blocked on CC-044, not dropped)

These items apply the moment `basedhuman-mcp` stops being a placeholder. They gate any npm
publish beyond the name reservation, exactly as CC-044 already records:

1. npm 2FA with a hardware key (YubiKey) on the publishing account.
2. Publish with GitHub Actions OIDC provenance (npm trusted publishing) so artifacts are
   attestable to the workflow that built them.
3. `npm audit signatures` clean in the package repo's CI.
4. Tight `.npmignore` scope — ship only the entry point, README, LICENSE and dist artifacts.
5. Dependabot on the package repo (the website repo already has it).
