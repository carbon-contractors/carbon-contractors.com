# CC-043 — Migrate off OnchainKit to standalone wagmi + viem

Migrated from NOR-288. Still outstanding — `package.json` has `@coinbase/onchainkit: ^1.1.2`.
Only two files affected: `src/lib/wallet/providers.tsx` and `src/components/NavBar.tsx`.
`wagmi 2.19.5` and `@tanstack/react-query 5` are already installed.

## Sequencing — read before starting CC-001 or CC-003
This overlaps two P0 launch blockers, and doing them in the wrong order wastes the work:

- **CC-003 (CSP)** exists purely because OnchainKit's default transport calls
  `api.developer.coinbase.com` and its passkey iframe comes from `keys.coinbase.com`.
  A standalone wagmi setup lets you choose your own transport, so the CSP allowlist you
  need is different — possibly smaller.
- **CC-001 (no mobile wallet button)** means touching `NavBar.tsx`, which is one of the two
  files this migration rewrites.

Decide up front: either do this migration first and fix CC-001/CC-003 against the new stack,
or explicitly accept doing that work twice. Given the launch is blocked on CC-001 and CC-003
anyway, doing the migration first is probably cheaper.

Related: CC-001, CC-003, CC-039.

## Update 2026-07-25 — an extra reason to do this, and a trap

`src/lib/wallet/providers.tsx` passes **no wagmi config and no connectors array** — it inherits
whatever OnchainKit's version happens to default to. That means the connector set, the RPC
transport, and therefore the CSP hosts required (CC-003) can all change under a patch bump,
silently.

That is a good argument for this migration: an explicit `createConfig` with a named connector list
makes the wallet stack legible and pins the hosts you need to allowlist.

**The trap:** the passkey Smart Wallet connector currently arrives by accident, via that default.
Once you write the config explicitly you must add it deliberately, or you will ship a build where
the only way to connect is a browser extension — silently removing every mobile user. Add
`baseAccount` (or the current equivalent) explicitly and re-run CC-055 afterwards.

Related: CC-055.

## Resolution

`src/lib/wallet/providers.tsx` now builds its own `createConfig` (`WagmiProvider` +
`QueryClientProvider`, no `OnchainKitProvider`) with an explicit connector list —
`baseAccount({ appName: "Carbon Contractors" })` first, `injected()` second — and `http()`
transports for both `base` and `baseSepolia` with no argument, which resolves to
`mainnet.base.org` / `sepolia.base.org`, both already in the CSP `connect-src` allowlist. No new
CSP entries were needed for RPC.

`src/components/NavBar.tsx` no longer imports `@coinbase/onchainkit/wallet` or `/identity`. It's a
small custom component now: a "Connect Wallet" button that opens a dropdown listing
`useConnect().connectors` when disconnected, or the truncated address with a disconnect option
when connected (no Basename/avatar resolution — that required the OnchainKit identity API host,
which is gone along with the package). `src/app/layout.tsx` dropped the OnchainKit stylesheet
import. `@coinbase/onchainkit` is removed from `package.json`
(`NEXT_PUBLIC_ONCHAINKIT_API_KEY` removed from `src/lib/config.ts` and every place that stubbed it
for tests/CI).

**Real bug found during the migration, not part of the plan:** `wagmi/connectors`'s `baseAccount()`
pulls in `@base-org/account`, whose Node SSR entry point (`dist/index.node.js`, reached via
`getOrCreateSubscriptionOwnerWallet.js`) imports a bundled `@coinbase/cdp-sdk` that calls `bs58` in
three files without declaring it as a dependency in its own `package.json`. `npm run typecheck`,
`npm run lint`, and the full `vitest` suite all stayed green through this — none of them render
`providers.tsx`, so none could catch a bundler-resolution failure. It only surfaced running the dev
server and loading the page in a browser, which is why that verification step is not optional for
frontend changes (see the new Lessons-Learned entry). Fixed by adding `bs58` directly as a
top-level dependency — Node's module resolution walks up from the nested import site to the
project's `node_modules/bs58`, so this satisfies it without patching the vendored package.

Verified: `npm run typecheck`, `npm run lint`, `npx vitest run` (80/80) all clean; `npm run build`
succeeds (all routes including `/`, `/connect`, `/dashboard` prerender); dev server loads with zero
server-side compile errors, NavBar renders "Connect Wallet", clicking it lists "Base Account" and
"Injected" as connectors, and picking "Injected" with no extension installed fails silently without
crashing the page (expected — there's nothing to connect to in this environment).

**Not done here, deliberately:** CC-003 (CSP `frame-src` for the passkey iframe) and CC-055 (an
actual end-to-end passkey registration) are separate issues, updated with what this migration
changes for them but not closed by it. CC-001 (mobile wallet button hidden) is next, on top of this
new `NavBar.tsx`.
