# CC-091 — Succession and disaster recovery

`docs/Key-Compromise-Recovery.md` covers the key being in the **wrong** hands. This is the key
being in **nobody's** hands. Same asset, opposite problem, and nothing in the repo addresses it —
searched 2026-08-15 for succession / bus factor / death / estate / incapacity / unavailability
across `docs/`: no hits.

The archetype is QuadrigaCX — CEO died in 2018 as sole holder of the cold wallet keys, ~$190M CAD
stranded permanently, never recovered.

## The good news, and it is not luck

`ADR-0001` Amendment 1 removed the platform from the settlement path entirely. As a direct
consequence, **every funded task still resolves correctly with the platform permanently gone**:

| Path | Caller | Survives? |
| :-- | :-- | :-- |
| `releaseAfterReview` | worker | ✅ pull payment, no platform involvement |
| `expireTask` | agent | ✅ pull payment, no platform involvement |
| `completeTask` | agent | ✅ agent-only |

A1.2 (pull payment) and D6 (liveness default to the worker) were chosen to stop platform inaction
deciding outcomes. Bus-factor resistance fell out of that for free. **Do not regress it** — any
future change that puts the platform back in the settlement path re-creates this exposure.

## The one genuine stranding case

**Tasks in `Disputed` or `Arbitrating`.** `resolveDispute` is `onlyOwner`, there is no timeout and
no fallback. If the owner key becomes unreachable, those funds are locked permanently. That is
precisely the QuadrigaCX shape, scoped down to disputed tasks.

Two related failures degrade but do **not** strand:

- **Signing key lost** → no verdicts can be issued → under D6 everything resolves to workers after
  the review window. Safe direction, and no money is trapped.
- **`setVerdictSigner` unreachable** → cannot rotate out of that state, but no funds are held.

## Two layers with different survival requirements

- **Funds** live on-chain and now survive the founder, except for the disputed case above.
- **Service** — GCP project, Cloud KMS, Vercel, Supabase, the domain, the GitHub org, the npm org —
  is entirely account-bound and dies with access to those accounts.

The site going dark is bad. It is not the thing that takes people's money. Keep the two separate
when reasoning about priority: this ticket is P1 because of the first layer, not the second.

## The lever already exists

`CC-090` proposes splitting the verdict signer from the contract owner. **The same change fixes
this**: moving ownership to a multisig rather than a single KMS key turns succession from a legal
problem into an operational one. A 2-of-3 where the founder does not hold every key means the
disputed-funds case has a path that does not depend on one person being alive and reachable.

`CC-090` was filed P2 on the reasoning that separation buys nothing while both roles sit on one
Vercel-reachable key. **Succession is a second, independent and stronger argument for the same
move.** Reconsider `CC-090`'s priority alongside this.

## Open questions — this probably graduates to an ADR

`CLAUDE.md` says a design question gets an ADR, not a guess. This has rejected alternatives and
consequences that outlive the decision, so it likely earns one rather than staying an issue.

- **Multisig owner: what threshold, and who holds the keys?** 2-of-3 needs two other people or two
  other custody mechanisms. Naming them is the hard part, not the contract change.
- **Should `Disputed` have a timeout at all?** A deadline that releases to *someone* removes the
  stranding case, but reintroduces "silence decides an outcome", which `ADR-0001` D6 rejected in a
  different context. Not obviously the same trade — worth deciding on its merits rather than by
  analogy.
- **GCP access succession.** Who else can reach the `carbon-contractors` project and impersonate
  `kms-signer-svc`? If the answer is "nobody", that is the single point of failure regardless of
  what the contract does.
- **Non-fund continuity**: domain renewal, Vercel and Supabase billing, the GitHub org. Cheap to
  document, and nothing documents it.
- **Does any of this need to exist in law rather than in code?** An estate cannot inherit a key it
  cannot find. Out of engineering scope; needs the same lawyer as `CC-051`.

## Timing

**Settle before `CC-039`.** Mainnet is the point at which the funds stop being play money, and the
migration is one-way. A succession posture decided afterwards is decided under pressure.
