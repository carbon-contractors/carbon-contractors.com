# CC-036 — Task completion attestations (EAS)

Listed as unchecked in the README project status, marked "roadmap, post-monetisation".
On-chain attestation per completed task, surfaced on the worker's reputation.

Currently reputation is computed from escrow event logs plus a DB fallback
(`src/lib/reputation/index.ts`), which works but is not independently verifiable by a third
party. Attestations are what make the reputation claim in the README actually true.

## Update 2026-08-10 — reclassified: public-launch, P0, not mainnet/P2

Found while sweeping the `/learn` docs for staleness: the homepage's own "How it works" copy and
`/learn/how-x402-pays-you` both describe a formal on-chain attestation as something that already
happens on every completed task. It doesn't — this issue was filed against the real gap, but
scoped as `epic: mainnet` / `P2`, i.e. "later, after real money." Aaron corrected that directly:
this is core to the pitch and needs to exist **before** the coming-soon gate comes off, not after.

Reclassified to `public-launch` / `P0` accordingly. Left the Learn docs and homepage copy with an
honest inline note that the formal attestation isn't live yet, rather than either overclaiming it
exists or stripping the concept out entirely — the copy describes what's true today (on-chain
event logs, independently recomputable, just not a formal EAS attestation object) and should have
that caveat sentence removed as part of closing this issue, once it's actually shipped.

Related: `docs/backlog/CC-070` (why the reputation event queries need fixing before this is even
usable at scale — chunked `eth_getLogs`, currently broken on any long-lived contract).

## Update 2026-08-11 — backlog triage pass

Reviewed in the triage pass — **stays P0**, by Aaron's explicit call.

For the record, because it cuts against the priority: the justification in the 2026-08-10 update has
partly expired. That update raised this to P0 because the homepage and Learn copy described formal
on-chain attestation as something that already happens. The Learn sweep (`b39745a`) has since
softened that — the homepage's step 3 now says "a permanent onchain record", which is accurate today
via escrow event logs. So there is no longer a live misrepresentation driving this.

Aaron's position on being shown that: attestations are core to the pitch and the caveat sentence is
an admission of a gap rather than a fix, so this ships before the gate lifts. Recorded rather than
silently re-prioritised.

Dependency unchanged: `CC-070` (now P0) must land first — the reputation event queries this builds
on are broken on any contract more than about an hour old.
