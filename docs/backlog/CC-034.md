# CC-034 — Mainnet deployment run

Section 3 of the MVP definition of done. **Do not start until the whole of `CC-076` (the Sepolia
validation gate) is clear.** This deliberately points at the hub rather than at named issues — it
previously read "do not start until CC-032 and CC-035 are green", which went stale within weeks when
`CC-035` became a day-of checklist line and `CC-032` was split four ways.

Fresh deployer wallet never used on testnet; deploy escrow to Base mainnet; authorise the
KMS-derived signer address on the contract; verify the derived address matches the contract
owner on Basescan; repoint every `NEXT_PUBLIC_*` contract address, `NEXT_PUBLIC_BASE_NETWORK`,
`NEXT_PUBLIC_BASE_URL` and `NEXT_PUBLIC_USDC_ADDRESS` to mainnet; confirm monitoring
(escrow balance, signer gas, function logs, Supabase logs).

Then one real small-value transaction end to end before any public announcement.

Note the KMS/HSM signer work is already done and tested (`src/lib/contracts/kms-signer.ts`,
`scripts/verify-kms-signer.ts`, attestation bundle in `docs/`), so the old raw-key blocker
is closed. Confirm `DEPLOYER_PRIVATE_KEY` is absent from all deployed environments.

## Update 2026-07-25

CC-039 is the consolidated go-live gate (from NOR-306) — treat that as the checklist and this as
the execution step.

Add to the deploy scope: the export also calls for a **Slither scan** and **Basescan source
verification** of the mainnet contract, neither of which was in the original checklist here.

And per CC-049, the mainnet deploy is the natural window to add a `completeTaskByOwner(taskId)`
emergency function — the current `Ownable` design leaves in-flight tasks stuck if the signer key
rotates, and a new deployment is the only cheap chance to fix it.
