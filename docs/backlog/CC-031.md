# CC-031 — Tip jar is dead on mobile and points at a Sepolia wallet

`src/components/BuyMeACoffee.tsx:75,105-107` requires a connected wallet, so it is unusable
on mobile for the same reason as CC-001. It also targets a real address
(`NEXT_PUBLIC_TIP_WALLET_ADDRESS`) while the app runs on Sepolia, so any tip would be test
USDC.

Separately, `.github/FUNDING.yml` sets `ko_fi: wahzammo`, which only affects the GitHub
sponsor button and is unrelated to the on-site jar.

Fix: either hide the tip jar until mainnet, or make the testnet caveat explicit. Decide
alongside CC-007.

---

## Update 2026-08-11 — backlog triage pass

Reviewed in the triage pass — **stays P2**, and the open question in the Fix section is now
**decided: hide the tip jar until mainnet.**

Aaron's call. Rationale: it removes the problem rather than caveating it, and it is consistent with
how `CC-007` was handled — since the coming-soon gate does not lift until after the mainnet
migration, there is no window in which the public sees a tip jar pointing at a Sepolia wallet. A
testnet caveat would be copy written to be deleted.

So the work here is: remove `BuyMeACoffee` from the UI now, and restore it as part of `CC-039`'s
content pass once real USDC is live — at which point the mobile wallet-connection requirement
(`src/components/BuyMeACoffee.tsx:75,105-107`) also needs revisiting on its own merits.

`.github/FUNDING.yml`'s `ko_fi: wahzammo` is unaffected, as this issue already notes.
