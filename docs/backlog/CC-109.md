# CC-109 — PO action: provision the R2 backup target

The engineering half of D8 shipped in `CC-107`. This is the half that needs the
Cloudflare account owner: the pipeline `/api/cron/backup-export` runs daily at 04:17 UTC
and currently 503s loudly on every run because its target is unprovisioned — by design
(`CC-107`'s fail-closed posture), not a defect. Every step here is a dashboard action.

## Why R2

- DNS is already on Cloudflare (BCP-DR D6: repointing without the host reachable), so
  this is the existing account — "independent external cold storage" without a new
  vendor relationship.
- Zero egress fees: cold-storage restore drills cost nothing to rehearse.
- S3-compatible API, so the exporter is one endpoint change away from AWS S3 if the
  vendor ever needs to change — the *off-vendor* property is what matters, not the brand.

## Steps (all in the Cloudflare dashboard, ~10 minutes)

1. **R2 → Create bucket** — suggested name `cc-tier1-backups`, default location.
   Note the 32-hex account id in the dashboard URL
   (`dash.cloudflare.com/<account-id>/r2/...`) — that is `R2_ACCOUNT_ID`.
2. **R2 → Manage R2 API Tokens → Create API Token** — permission **Object Read &
   Write**, scope **Apply to specific buckets only → cc-tier1-backups**. Create, copy
   the Access Key ID and Secret — the secret is shown once.
3. **Vercel → carbon-contractors.com → Settings → Environment Variables** (Production):
   - `R2_ACCOUNT_ID` = the 32-hex id
   - `R2_ACCESS_KEY_ID` = from step 2
   - `R2_SECRET_ACCESS_KEY` = from step 2
   - `BACKUP_R2_BUCKET` = `cc-tier1-backups`
4. **Optional but recommended — dead-man's switch:** create a check at
   healthchecks.io (free tier), period 1 day, grace 6h. Add
   `BACKUP_HEARTBEAT_URL` = the ping URL to Vercel. The cron pings it only on a
   fully-verified run; healthchecks.io emails when the daily ping stops arriving.
   Without it, a silently-dead cron looks identical to a healthy one.
5. **Trigger the first run:** `curl -H "Authorization: Bearer $CRON_SECRET"
   https://carbon-contractors.com/api/cron/backup-export` — expect `ok: true` and
   per-table rows/sha256s in the response, then confirm the objects appear in the R2
   bucket under `tier1-backup/<project-ref>/…`.
6. **Independent verify** (any machine with the four vars in `.env.local`):
   `npm run verify:backup -- --prefix=<the prefix from step 5's response>`.

## Acceptance

- [ ] Four env vars set in Vercel Production
- [ ] First live run: `ok: true`, all Tier 1 tables `exported` (or `absent` for
