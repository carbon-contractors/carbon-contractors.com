# CC-052 — Local dev signer key is probably no longer authorised on the contract

## Problem
`.env.local` contains no `GCP_*` variables, so `getSigner()`
(`src/lib/contracts/signer.ts:49-59`) falls back to `DEPLOYER_PRIVATE_KEY` — the documented
local-dev path, and correct by design.

But NOR-196 moved contract authority to the KMS-derived address. So the raw key in
`.env.local` is very likely **not** the owner or authorised signer any more. Local calls to
`completeTaskOnChain`, `resolveDisputeOnChain` or `expireTaskOnChain` will revert, and the
error will look like a code bug rather than an authorisation problem.

This will be the first wall hit when testing the task lifecycle locally (CC-032).

## Do
1. Derive the Ethereum address from `docs/carbon-contractors-escrow-signer-1.pub` and compare
   it against the current `owner()` on the Sepolia escrow contract via Basescan. That settles
   which key actually holds authority.
2. Decide the local story: either point local dev at KMS through gcloud ADC (a commit on the
   KMS branch already added "auto-detect Vercel runtime and fall back to ADC locally", and
   `scripts/verify-kms-signer.ts` exists to check it), or accept that local escrow writes
   cannot work and test those paths against a preview deployment only.
3. Whichever you choose, write it down in the README — this is exactly the kind of thing that
   costs an evening after a gap.

## Also
`.env.local` is missing `BASE_SEPOLIA_RPC_URL` and `NEXT_PUBLIC_BASE_URL`. Both are optional
with defaults, so not breaking, but the RPC default means you are on the public
`sepolia.base.org` endpoint and subject to its rate limits (which is the motivation for CC-048).

Related: CC-032, CC-048, CC-053.

## Closed 2026-07-30 — measured. **The premise was wrong, and backwards.**

The title of this issue is false. `scripts/audit/verify-contract-owner.mjs` (added in this commit)
read the live contracts on Base Sepolia:

```
HSM key, derived offline from docs/carbon-contractors-escrow-signer-1.pub
                          0xa8931097540e69B474013D294d0bA6A2cC853e4b   0.101   ETH
local DEPLOYER_PRIVATE_KEY
                          0x7863A5c4396E7aaac2e99Cb649a7Aa4F6A36B91b   0.1866  ETH

CarbonEscrow.owner()    = 0x7863A5c4396E7aaac2e99Cb649a7Aa4F6A36B91b   <- the local key
ReputationStake.owner() = 0x7863A5c4396E7aaac2e99Cb649a7Aa4F6A36B91b
totalLocked()           = 0
```

**The local key is the owner of both contracts.** `NOR-196` built the KMS signer and funded its
address but never called `transferOwnership()`. So:

- Local `resolveDisputeOnChain` will **not** revert. The concern in this issue does not exist.
- No gcloud/ADC setup is needed for local dev to work. It already works.
- `BASE_SEPOLIA_RPC_URL` and `NEXT_PUBLIC_BASE_URL` are still absent from `.env.local` as noted in
  "Also" above. The public-RPC consequence is now evidenced rather than theoretical — it makes the
  test suite flaky. See `CC-060` and `CC-048`.

### The real problem is the inverse, and it moved to CC-059

If Vercel production has `GCP_KMS_KEY_PATH` set, then *production* signs as `0xa8931097…`, which is
not the owner, so dispute resolution reverts **in production** rather than locally — the opposite of
what this issue and the `CLAUDE.md` landmine both predicted. And `docs/Security-Trust-Disclosure.md`
publicly claimed the HSM key owns the escrow, inviting readers to check on Basescan, where it fails.

That is tracked as **`CC-059`**, which also carries the corrected documentation. `CLAUDE.md`'s
landmine has been rewritten. Nothing further to do here.

### Item 3 of "Do" — write it down

Done, in `README.md`: local escrow writes work because the local key holds owner authority, and that
is a defect rather than a convenience, pending `CC-059`.
