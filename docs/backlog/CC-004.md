# CC-004 — /api/dispute is unauthenticated and live right now

## Problem
`src/app/api/dispute/route.ts:14-41` takes a `payment_request_id` and flips the task to
`disputed` with **no authentication of any kind** — no signature, no wallet header, no session.

This is reachable on the live site today: `middleware.ts:63-69` bypasses `/api/*` for the
coming-soon gate, so the endpoint is public while the rest of the site is dark.

Any anonymous caller who can guess or obtain a `payment_request_id` can freeze payment on
any task.

## Fix
Require a wallet signature matching `task.to_human_wallet`. The MCP path already does this
correctly — mirror the challenge-response pattern from `src/lib/mcp/server.ts:311,730` and
`src/app/api/basedhuman.mcp/route.ts:89-141`.

## Acceptance
Unsigned POST returns 401. Signed POST from a wallet other than the assigned worker returns 403.
