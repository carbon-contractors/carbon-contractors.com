# CC-118 — Monitoring & alerting v2 (hub): the watch surface

Hub ticket. Not itself actionable; it defines "done" for the Linear epic *Monitoring &
Alerting — the watch surface*, whose sub-issues each name this id as their parent. Design:
`ADR-0011` (proposed).

## Problem

Pre-launch, with no real money on chain, the monitoring from `ADR-0003` has already produced
alert fatigue severe enough that the only responder is tuning it out. Measured 2026-09-25:

- Every scheduled run 2026-09-15 → 2026-09-25 was red; **zero were breaches**. Causes were all
  in the watching: a tightened public-RPC `eth_getLogs` cap (1,000 blocks) mislabelled as
  transient; the CDN refusing GitHub's IPs on `/api/health`, reported as a breach; a missing
  env var.
- The hourly schedule fires 5–7×/day; the stateless rescan (~1.05M blocks and growing ~43k/day)
  cannot complete on the public endpoint at its cap; each red run pages three channels and
  repeats every run with no "resolved".
- There is nowhere to *look*. The only view of platform state is a push notification or an
  Actions log.

The PO requirement (a design constraint, `ADR-0011` D6): a `wazuh-manager` for Carbon
Contractors — one place to see state, and a notification **only** when something needs
attention and action. One channel: Telegram.

## Scope

`ADR-0011` handover items 1–9: RPC provider (D1), stateful incremental collection with weekly
reconciliation (D2), freshness-aware scheduling (D3), the owner-only `/ops` dashboard (D4), the
incident state machine and paging policy (D5), the app-error relay (D7), mainnet cut-over.
Item 10 (independent witness node) is explicitly deferred past mainnet.

## Acceptance

- [ ] `ADR-0011` accepted by the PO, with its four open items answered.
- [ ] Money checks read through a dedicated RPC; no scheduled run is red because of the RPC's
      range cap or rate limit.
- [ ] Sweeping checks are incremental (cursor + overlap) and a weekly full rescan reconciles
      the stored state against the chain, alarming on any difference.
- [ ] Every check result is persisted; `/ops` shows money-safety, open incidents, freshness and
      activity, gated to the owner, reachable from every page.
- [ ] Pages happen only on: a breach, or a check blind beyond its tolerance — once per incident,
      with one "resolved" message; every page states whether money is at risk and the one next
      action. Telegram is the only paging channel.
- [ ] A 14-day window on testnet with **zero pages that did not require action** (the
      measurable form of "only when it needs me").
- [ ] Mainnet collection, tolerances and runbook in place before `CC-039`'s smoke test.
