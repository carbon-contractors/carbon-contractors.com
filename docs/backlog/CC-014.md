# CC-014 — Flipping the coming-soon gate requires a redeploy, not just an env change

## Problem
`middleware.ts:19` and `src/app/page.tsx:4` both read `NEXT_PUBLIC_COMING_SOON` at module
scope. Next.js inlines `NEXT_PUBLIC_*` at build time, and `/` is statically prerendered.

Setting the Vercel env var alone will appear to do nothing. Easy to lose an hour to this.

Also note the flag fails **closed** (`!== "false"`), so the string must be exactly `false`.

## Fix — launch runbook
1. Confirm all five vars required by `src/lib/config.ts` are present in the Vercel
   **Production** environment at build time: `SUPABASE_URL`, `SUPABASE_ANON_KEY`,
   `SUPABASE_SERVICE_ROLE_KEY`, `NEXT_PUBLIC_BASE_NETWORK`, `NEXT_PUBLIC_USDC_ADDRESS`.
   Line anchors drift — the required set is whatever sits in the `envSchema` block as a
   bare required schema (no `envOptional` wrapper). Blanked fields read as unset (`CC-097`),
   so a blank Vercel field is a *missing* var, not a set one.
2. Set `NEXT_PUBLIC_COMING_SOON=false`.
3. Trigger a fresh production deploy (do not promote an old build).
4. Verify `/connect` returns 200 rather than redirecting to `/`.
5. Walk the full signup path on production, on a phone, with the console open.

## Update 2026-08-15 — the MCP endpoint is already publicly documented and already live

Everything above concerns copy on a site behind the gate. **This does not.**
[`carbon-contractors/basedhuman-mcp`](https://github.com/carbon-contractors/basedhuman-mcp) has
been public since March 2026 and its README instructs anyone to add the endpoint to their agent
config. Probed 2026-08-15: `initialize` returns `200` with a session id, and `tools/list` returns
**all ten tools, unauthenticated**, including `request_human_work`, `dispute_task` and
`resolve_dispute`.

`/api/*` bypasses the coming-soon gate by design, so **the gate has never covered any of this.** A
stranger's agent can hire through this platform today. Nothing is at risk while the escrow is on
Sepolia and the USDC is worthless — but the instructions are already published, so mainnet is the
moment they become an instruction to lose real money via `CC-081` Defect 1's stranding funding path.

Because that repo is outside this one, nothing in this repo's CI, tests or audit scripts can see it.
It has to be a checklist item or it will be missed.
