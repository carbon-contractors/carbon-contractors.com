# CC-014 — Flipping the coming-soon gate requires a redeploy, not just an env change

## Problem
`middleware.ts:19` and `src/app/page.tsx:4` both read `NEXT_PUBLIC_COMING_SOON` at module
scope. Next.js inlines `NEXT_PUBLIC_*` at build time, and `/` is statically prerendered.

Setting the Vercel env var alone will appear to do nothing. Easy to lose an hour to this.

Also note the flag fails **closed** (`!== "false"`), so the string must be exactly `false`.

## Fix — launch runbook
1. Confirm all six vars required by `src/lib/config.ts:11-26` are present in the Vercel
   **Production** environment at build time.
2. Set `NEXT_PUBLIC_COMING_SOON=false`.
3. Trigger a fresh production deploy (do not promote an old build).
4. Verify `/connect` returns 200 rather than redirecting to `/`.
5. Walk the full signup path on production, on a phone, with the console open.

## Update 2026-08-15 — the MCP endpoint is already publicly documented and already live

Everything above concerns copy on a site behind the gate. **This does not.**
[`carbon-contractors/basedhuman-mcp`](https://github.com/carbon-contractors/basedhuman-mcp) has
been public since March 2026 and its README instructs anyone to add the endpoint to their agent
config. Probed 2026-08-15: `initialize` returns `200` with a session id, and `tools/list` returns
**all ten tools, unauthenticated**, including `request_human_work`, `dispute_task` and
`resolve_dispute`.

`/api/*` bypasses the coming-soon gate by design, so **the gate has never covered any of this.** A
stranger's agent can hire through this platform today. Nothing is at risk while the escrow is on
Sepolia and the USDC is worthless — but the instructions are already published, so mainnet is the
moment they become an instruction to lose real money via `CC-081` Defect 1's stranding funding path.

Because that repo is outside this one, nothing in this repo's CI, tests or audit scripts can see it.
It has to be a checklist item or it will be missed.

**Add to the runbook, before step 2:**

- [ ] `request_human_work` is authenticated and `from_agent_wallet` is bound to the caller
      (`CC-081` Defect 4) — otherwise any anonymous caller can create tasks against the live escrow.
- [ ] `/api/fund-task` no longer strands USDC (`CC-081` Defect 1) — this is the one that turns a
      published connect instruction into a published way to lose money.
- [ ] `resolve_dispute` has lost agent authority in the app layer (`CC-081` Defect 2).
- [ ] `basedhuman-mcp`'s README describes what the endpoint actually does on mainnet, and its
      connect URL still resolves without a redirect (fixed to `www.` on 2026-08-15 — the apex
      `307`s, which not every MCP client survives on a `POST`).
- [ ] **`basedhuman-mcp` has branch protection.** Measured 2026-08-15: this repo enforces a
      ruleset (`protect_main_branch` — `required_signatures`, `code_scanning`, `code_quality`,
      `deletion`, `non_fast_forward`) and **`basedhuman-mcp` has no rulesets and no branch
      protection at all.** The asymmetry is backwards. Since npm is not the distribution
      channel, that README *is* the distribution mechanism, and the integrity of one URL line
      is the integrity of the whole connect path: point it at a hostile host and every agent
      following those instructions hands task payloads and wallet addresses to someone else's
      MCP server. Unusually, the docs are the attack surface and the code is inert.
      `required_signatures` is the item that carries the weight — it means nothing lands there
      without a physical YubiKey touch, which is what stops an unattended or automated push.
      `code_scanning` and `code_quality` are ceremony on a repo whose only `.js` file is a
      `console.log`. Also review the collaborator list while there.
- [ ] A decision has been made and recorded on **registry listings** (official MCP Registry,
      Smithery, mcp.so, Glama and similar) and on **npm publication**. Neither has happened.
      `ADR-0004`'s "copy describes the target state" does **not** extend to either: forward-looking
      marketing copy is a deliberate choice, whereas a registry entry is a durable public
      endorsement and a package that installs and fails is simply broken. Note npm is not on the
      critical path at all — this server has been remote streamable-HTTP since its first commit and
      has never had a stdio transport, so agents connect by URL and install nothing.

Priority stays **P2** — it is still a runbook, not a defect.
